# はじめに

[English](../getting-started.md) · [简体中文](../zh/getting-started.md) · [ドキュメント](../../README.ja.md)

## インストールとプロジェクトの起動

Bun と端末が必要です。Amira をチェックアウトしたディレクトリで、次のコマンドを実行してください。

```sh
bun install
cd packages/cli
bun link
cd ../..
```

CLI パッケージは、グローバルな `amira` 実行ファイルを定義しています。Bun の実行ファイルがあるディレクトリを PATH に追加してください。開発中は、リポジトリのルートから `bun run amira` を実行すると、同じ CLI が起動します。

Amira に作業してもらうプロジェクトのディレクトリに移動し、次のコマンドを実行してください。

```sh
amira
```

作業ディレクトリは現在のディレクトリです。`--cwd` で別のディレクトリを指定できます。Amira は全画面の会話画面を開き、バナー、作業ディレクトリ、ステータス領域、`Message Amira` 入力欄を表示します。端末のスクロールバックを使いたい場合は、`--inline` を指定してください。プロジェクトに拡張機能がインストールされている場合、メイン画面の前に信頼するかどうかを確認するプロンプトが表示されることがあります。拡張機能はコードを実行するため、このプロジェクトのパッケージを読み込むかどうかを選んでください。[拡張機能](extensions.md)を参照してください。

プロバイダーが設定されていない場合、ウェルカムカードには次のように表示されます。

```text
Welcome to Amira. Three steps to a first message:
1. Add a provider: /provider add
2. Pick one of its models: /model
3. Ask away: @ mentions files, /help lists the commands and keys
```

## プロバイダーの追加

`/provider add` を入力して Enter を押してください。ベンダー一覧を名前または ID で検索します。ベンダー情報は models.dev カタログから取得します。対応するベンダーを選ぶと、`Add a provider` フォームが開き、編集可能な `Id`（ローカルで使うプロバイダー名）、プロトコル、`Base URL` が事前入力されます。ID がすでに使われている場合は、Amira が `-2` などの接尾辞を提案します。ローカルサービスや一覧にないサービスには `Custom` を選び、`openai-chat`、`openai-responses`、`anthropic-messages`、`google-gemini` のいずれかを選択して、URL を入力してください。オフラインでカタログを利用できない場合も、`Custom` を使います。未対応のベンダーでは、プロトコルと URL を手動で選ぶ必要があります。

デフォルトのキーの取得元は保存済みの API キーで、入力内容はマスクされます。ベンダーに登録されている環境変数のいずれかがすでに設定されている場合、フォームは環境変数による認証を選択し、値ではなく変数名だけを表示します。そうでない場合は、`Environment variable` を選ぶと、一覧の最初の変数名が事前入力されます。`Environment variable` は編集できます。このフィールドに対応する設定は `apiKeyEnv` で、秘密の値ではなく変数名を保存します。Amira を起動する前に、シェルでその変数を設定してください。認証が不要なローカルサーバーには、`No key` を選んでください。認証には保存済みの API キー、環境変数、キーなしを使用でき、OAuth には対応していません。

`Models` では、`Fetch models` を選んでエンドポイントから利用可能なモデルを取得するか、正確なモデル ID を自分で入力してください。取得時には、フォームで指定したキーを使ってリクエストを送信します。一覧は独自の ID にも対応しています。Space で行を選択でき、ID を入力して Enter を押すと追加できます。モデル ID とコンテキストウィンドウは、利用するサービスと一致している必要があります。カタログにないモデルの上限を指定する必要がある場合は、`Defaults for models the catalog does not know` を展開してください。`Test connection` は任意です。小さなモデルリクエストを送信するため、料金が発生する場合があります。`Save` はプロバイダーをユーザー設定に書き込みます。Esc は保存せずにキャンセルします。エンドポイントのパス、キーの優先順位、互換性の設定については、[プロバイダー](providers.md)を参照してください。

## モデルの選択

`/model` を実行して設定済みのモデルから選ぶか、実際のプロバイダー ID とモデル ID を使って `/model provider/model` を実行してください。モデルを含む最初のプロバイダーを保存すると、その最初のモデルがすでに選択されている場合があります。`/model` で確認または変更してください。以降の起動では、`--model`、`AMIRA_MODEL`、`model` 設定の順に優先されます。いずれも指定されていなければ、設定済みのプロバイダーが 1 つだけの場合、その最初のモデルを使います。複数のプロバイダーがあり、デフォルトのモデルがない場合は、明示的に選んでください。

利用可能なモデルがない状態でメッセージを送信すると、下書きは入力欄に残り、必要な設定が表示されます。設定用のコマンドは引き続き実行できます。

## 最初のタスクの完了

まずは、結果が明確なリクエストから始めてください。たとえば、次のように依頼できます。

```text
Read @README.md and the project configuration. Explain how to run the tests, then fix one failing test and verify the change.
```

この例を、実際のプロジェクトのファイルとタスクに置き換えてください。`@` とパスの一部を入力すると、ファイル選択画面が開きます。矢印キーで候補を選び、Tab または Enter でパスを挿入します。メンションはリクエストにテキストを挿入するだけで、ファイルの内容を自動的に添付するわけではありません。エージェントはツールでそのファイルを読み取れます。

Enter でリクエストを送信します。会話には返信が逐次表示され、ツールの動作も表示されます。承認の依頼や質問には、ダイアログで回答してください。確認ダイアログでは、最初は何も選択されていません。Enter で確定する前に、選択肢を選んでください。承認ダイアログで Esc を押すと、その呼び出しを拒否してターンを停止します。実行中に Enter で追加の指示を送ることも、入力欄の下に表示されるキュー用のキーを使って、完了後に送信することもできます。Esc で中断すると、待機中のメッセージが元の順序でまとめて送信されます。Esc を 2 回押すと、保存済みセッションの巻き戻し選択画面が開きますが、ディスク上の編集は元に戻しません。

`/status` でコンテキストの使用状況と報告されたコストを確認できます。実際の結果を確認するために、プロジェクトのテストを実行し、差分を確認してください。`/quit` で終了すると、Amira は会話を保存し、再開用のコマンドを表示します。`amira -c` は同じディレクトリの最新のセッションを続行し、`amira -r` はセッション選択画面を開きます。

## 次に試すこと

入力欄が空の状態で `?` を入力すると、キー操作のリファレンスが開きます。`/help` はコマンド一覧を表示し、`/` はコマンドの補完候補を開きます。`$` は検出されたスキルを一覧表示します。`$<name> [arguments]` は、該当するスキルが利用可能であれば実行します。対応する拡張機能やスキルがない場合、これらの一覧は空になります。
