# キー割り当て

[English](../keybindings.md) · [简体中文](../zh/keybindings.md) · [ドキュメント](../../README.ja.md)

対話 UI が受け付ける各キーは、アクションに対応しています。キーを変更するには、`~/.amira/keybindings.json`（または `$AMIRA_HOME/keybindings.json`）に、アクション名を 1 つのキーまたはキーの一覧へ対応付ける JSON オブジェクトを置きます。

```json
{
  "queue": "ctrl+b",
  "newline": ["shift+enter", "ctrl+j"],
  "redraw": []
}
```

- キーを指定すると、そのアクションのデフォルトのキーをすべて置き換えます。空の一覧は割り当てを解除します。
- アクションの最初のキーをヒント行に表示します（`newline` では端末が通知できる最初のキーです）。
- 入力欄の下のヒント行は、その時点で重要な少数のキーだけを表示します。待機中は `Enter send · ? keys`（入力があると `? keys` の代わりに `Shift+Enter newline`）、ターンの実行中は `Enter steer · Alt+Enter queue · Esc interrupt` です（実行中の指示やキュー内のメッセージが待っていると `Esc send queued`、セッションが保存されている場合は `Esc Esc rewind` も表示します）。一覧、履歴検索、検索バー、ブロック選択には、それぞれ専用のヒントを表示します。`?`（`help` アクション）でキーリファレンスが開き、すべてのアクション、現在の割り当て、このファイルで使うアクション名を確認できます。
- ファイルは起動時に読み込みます。不明なアクション、読み取れないキー、同じ場所で 2 つのアクションに割り当てられたキーは起動時に警告しますが、残りの設定は適用します。ファイルが有効な JSON でない場合はデフォルトのキーを使います。

## キーの指定形式

修飾キーとキーを `+` でつなげて指定します。大文字と小文字は区別しません。例：`ctrl+q`、`alt+enter`、`shift+tab`、`escape`、`y`。

- 修飾キー：`ctrl`、`alt`（`option`、`meta` も使用できます）、`shift`。
- キー：`enter`、`tab`、`escape`（`esc`）、`backspace`、`delete`、`insert`、`space`、`up`、`down`、`left`、`right`、`home`、`end`、`pageup`、`pagedown`、`f1`〜`f12`、または 1 文字です。`ctrl++` は Ctrl とプラスキーです。
- 通常の文字は Shift の有無にかかわらず一致します（`y` は `Y` にも一致します）。名前付きのキーやショートカットは Shift の有無を厳密に区別します。`enter` は `shift+enter` とは異なります。

端末によっては Amira に届かないキーがあります。Shift+Enter は、それを通知する端末（Windows Terminal、VS Code、kitty keyboard protocol 対応の他の端末）が必要です。それ以外では Ctrl+Enter が改行キーになります。端末やエディターがキーを自身の操作に使う場合もあります。Windows Terminal は Alt+Enter（全画面表示）、VS Code は Ctrl+Q（Quick Open View）を使います。VS Code では `terminal.integrated.commandsToSkipShell` から該当キーを除く必要があります。

## アクション

### 入力

| アクション | デフォルトのキー | 動作 |
| --- | --- | --- |
| `submit` | `enter` | メッセージを送信します。ターンの実行中は実行中の指示として送ります（`tui.submitWhileWorking: "queue"` ではキューに追加します） |
| `newline` | `shift+enter`, `ctrl+enter` | 改行を挿入します |
| `paste.image` | `alt+v`, `ctrl+v`, `shift+insert` | クリップボードのテキストを貼り付け、テキストがなければ画像を添付します（[画像](usage.md#画像)を参照）。Windows Terminal、VS Code などは Ctrl+V や Shift+Insert を自身の貼り付けに使います。Alt+V は Amira に届きます（macOS では Option を Meta として動作するよう設定します） |
| `queue` | `alt+enter`, `ctrl+q`（Windows では VS Code を除き `ctrl+q` が先頭） | ターンの実行中は、その終了後にメッセージを送信します（`tui.submitWhileWorking: "queue"` では実行中の指示として送ります） |
| `submit.steer` | なし | メッセージを送信します。ターンの実行中は常に実行中の指示として送ります |
| `submit.queue` | なし | メッセージを送信します。ターンの実行中は常にターン終了後に送ります |
| `interrupt` | `escape` | 実行中のコマンドをキャンセルし、入力を保持します。それ以外では実行中のターンを停止します。実行中の指示やキュー内のメッセージが待機していれば、入力順に 1 つにまとめて直ちに送信します。続けて 2 回押すと（待機中でも）、新しい順にユーザーメッセージを並べた巻き戻しの選択画面が開きます。選んだメッセージとそれ以降を会話から除き、入力欄へ戻して編集・再送信できます。`f` は代わりにその直前から新しいセッションへフォークし、現在のセッションを全体のまま残します。ファイルは復元しません |
| `cancel` | `ctrl+c` | 実行中のコマンドをキャンセルし、入力を保持します。それ以外では実行中のターンを停止し（待機中の指示やキュー内のメッセージは `interrupt` と同じように送信します）、実行中でなければ入力を消去し、入力もなければ終了します |
| `exit` | `ctrl+d` | 入力が空で、何も実行していなければ終了します |
| `redraw` | `ctrl+l` | 画面を消去し、最新の会話記録と入力欄を再描画します |
| `history.prev` | `up` | 入力の最初の行から、前のプロンプトを呼び出します |
| `history.next` | `down` | 入力の最後の行から、次のプロンプトを呼び出します |
| `history.search` | `ctrl+r` | プロンプト履歴を検索します |
| `tool-output` | `ctrl+o` | ツール出力の要約表示と完全表示を切り替えます。折りたたみ表示からは要約表示に戻ります |
| `panels.toggle` | `ctrl+t` | 実行状況行の上のライブパネル（実行中のバックグラウンドジョブや拡張機能のタスクリストなど）をそれぞれ 1 行に折りたたむか、展開します |
| `permissions.mode` | `shift+tab` | [権限モード](usage.md#権限)を `auto`、`edits`（ファイル変更は許可し、シェルコマンドは確認）、`plan`（読み取り専用）の順に切り替えます。ヒント行は新しいモードの動作を示し、`auto` 以外は入力欄の枠内でモデル名の横に表示します。サブエージェントを含むセッション全体に適用します |
| `copy.reply` | `alt+c` | セッションの最後の回答を Markdown としてクリップボードへコピーします |
| `help` | `?` | 入力が空でダイアログや一覧が開いていない場合、キーリファレンスを開きます（入力がある場合は `?` を入力します）。↑↓、PgUp/PgDn、Home/End でスクロールし、Esc、`q`、`?` で閉じます |
| `edit.kill-to-start` | `ctrl+u` | 行頭からキャレットまでを切り取ります（行頭では直前の改行を切り取ります） |
| `edit.kill-to-end` | `ctrl+k` | キャレットから行末までを切り取ります（行末では直後の改行を切り取ります） |
| `edit.kill-word` | `ctrl+w` | キャレットの前の単語を切り取ります |
| `edit.yank` | `ctrl+y` | 最後に切り取ったテキストを貼り付けます。連続した切り取りは 1 つにまとめます。折りたたまれた貼り付けはその状態を維持します |
| `edit.undo` | `ctrl+z` | 入力に対する最後の変更（入力した単語、連続した削除、切り取り、貼り付け、呼び出したプロンプト）を元に戻します |
| `edit.redo` | `ctrl+shift+z` | 最後に元に戻した変更をやり直します。kitty keyboard protocol 非対応の端末は Ctrl+Shift+Z を Ctrl+Z として送信するので、別のキーを割り当ててください |
| `edit.external` | `ctrl+g` | エディターでメッセージを編集します。`$VISUAL`、`$EDITOR`、Git の `core.editor`（`code --wait` などのコマンド）の順に使い、どれもなければ Windows では Notepad、他では vi を使います。終了まで端末をエディターに渡し、保存したテキストを入力に反映します |

[拡張機能が所有する永続的な会話](extensions.md#拡張機能が所有する永続的な会話)にネイティブフォーカスがある場合、F6（`view.focus` または設定したキー）でメインへ戻り、どちらの会話も停止しません。フォーカス中の会話が待機中で入力欄が空なら Esc（`interrupt`）でも戻れます。実行中の Esc/Ctrl+C（`interrupt`/`cancel`）はその会話だけを停止し、バックグラウンドのメインは停止しません。ダイアログ、補完一覧、履歴検索のキー優先順位は変わりません。下書き、プロンプト履歴、画像、貼り付け内容は会話ごとに保持し、`@` のファイル補完はその会話の作業ディレクトリを使います。スラッシュコマンドとスキルは実行せずヒントを表示します。メインへ戻り、明示的に実行してください。

### 補完一覧

入力が `/` で始まるとコマンドのポップアップ、`$` で始まるとスキルのポップアップ、`@word` を入力するとファイル一覧を表示します。これらのキーは入力欄より優先されます。`/` または `$` だけでは未選択で、項目を選ぶまで Enter は何もしません（最初の ↓ で先頭行を選びます）。スキルのポップアップで Enter が選択中のスキルを実行するのは、項目を選んだ場合か、入力した名前がそのスキル名の先頭部分に一致する場合だけです。`$` に続く他のテキスト（`$100 is the price`）はメッセージとして送信します。一致する項目がない名前では `no command matches /zzz` と表示して一覧を開いたままにします。`$zzz` だけの場合は、Esc で一覧を閉じるまで送信しません。

| アクション | デフォルトのキー | 動作 |
| --- | --- | --- |
| `popup.up` | `up` | 前のコマンド、スキル、引数、ファイルを選びます |
| `popup.down` | `down` | 次のコマンド、スキル、引数、ファイルを選びます |
| `popup.complete` | `tab` | 選択中のコマンド、スキル、引数を補完し、ファイルを挿入します |
| `popup.accept` | `enter` | コマンドやスキルを実行し、ファイルを挿入します |
| `popup.close` | `escape` | テキストが変わるまで一覧を閉じます |

### 履歴検索

履歴検索中に入力すると結果を絞り込みます。他のキー（矢印キーなど）は、一致した内容を入力欄に残して検索を終了し、そのキー本来の操作を行います。

| アクション | デフォルトのキー | 動作 |
| --- | --- | --- |
| `search.older` | `ctrl+r` | 次の古い一致を表示します |
| `search.newer` | `ctrl+s` | 次の新しい一致を表示します |
| `search.accept` | `enter` | 一致した内容を入力欄に残し、編集や送信ができるようにします |
| `search.cancel` | `escape`, `ctrl+c`, `ctrl+g` | 下書きを戻して検索を終了します |

### ダイアログ

承認などの確認、一覧、差分レビュー、テキスト入力、モデルの質問（ask_user）は、インラインで回答します。それぞれ、左の縦線、質問、選択肢、キーを持つブロックです。選択肢が 9 個までの一覧（確認画面を除きます）では、先頭の数字で選択し、複数選択ならチェックします。`Other…` はその行に自由回答のテキスト欄を開きます。Enter でテキストを保持し、Esc で欄を閉じます（もう一度 Esc を押すとダイアログをキャンセルします）。複数の質問は同じブロックで順に尋ね、まとめて回答します。Enter で次の質問へ進み、後の質問で Esc を押すと、回答を保持して前の質問へ戻ります。

一覧によっては、専用キーを持つセクションに分かれています。そのセクションの項目を選択中はヒント行にキーを表示し、キーを押すと選択中の項目に対して回答します。`/agents` の一覧では、サブエージェントで Enter を押すとライブビューアーが開き、`p` は代わりに会話記録を会話内へ出力します。サブエージェントが保持した worktree で Enter を押すと差分を表示し、マージ、保持、破棄を選べます。`/jobs` の一覧（モデルが起動した開発サーバーなどのバックグラウンドジョブ）では、Enter で出力のライブ表示、`x` で停止、`p` で出力末尾を会話内へ出力します。

`/ext` では Enter でインストール済み拡張機能を管理するか、インデックスからインストールします。`d` で選択中の拡張機能の詳細を表示します。入力すると一覧を絞り込みます。フィルターにテキストが入ると、`d` もフィルターの一部になります。インストール・更新中も入力は利用でき、ライブの進捗パネルを表示します。ダイアログや補完一覧の外では、Esc（`interrupt`）または Ctrl+C（`cancel`）で実行中のコマンドをキャンセルし、下書きを保持します。完了済みの変更はインストールされたままです。ヒントは現在のキー割り当てを使います。パッケージの変更は待機中の `/reload` で反映します。設定を宣言した読み込み済みの拡張機能には **Settings** も表示します。単独ファイルは **Standalone** に表示され、Settings と Show details だけを利用できます。`/ext config <name>` はそのページを直接開きます。名前は `/ext` に表示される、ホストがファイル名から導いた名前（例：`my-extension`）です。衝突すると `-2`、`-3` を付けます。パッケージ名との衝突も含みます。引用符付きの絶対パスも使えます。`/ext config "/path/to/my extension.ts"` または `/ext config "C:\\extensions\\my extension.ts"` です。これらのコマンド名は、単独ファイルの設定を絶対パスで識別する保存方式を変更しません。ライブプレビューは保存済みの値を変更しません。上下で行を選択し、左右または `-`/`+` で数値を調整し、数字で範囲内の値を設定し、左右で選択肢を切り替え、space でオン・オフを切り替えます。テキストと色は 1 行の入力欄です。`ctrl+r` でフォーカス中の行をデフォルト値に戻します。Enter でユーザー設定かプロジェクト設定かをインラインで尋ね、もう一度 Enter を押すと保存して拡張機能へ即座に通知します。Esc は下書きを破棄します。説明はフォーカス中の行の下で折り返し、デフォルト値と異なる値には印を付けます。

`/provider` の先頭の **+ Add provider** で追加を開始し、プロバイダーで Enter を押すと編集、キー設定、接続テスト、削除を選べます。Esc でページを閉じます。全画面フォームの複数選択欄では、入力で ID とラベルを絞り込み、Backspace でフィルターを編集し、Space で選択を切り替えます。Ctrl+A はフィルターに一致する項目をすべて選択または解除し、Ctrl+X はその選択を反転します。画面外の一致行も対象です。フィルター外の選択は保持されます。Esc は空でないフィルターを先に消し、その後フォームをキャンセルします。これらはフィールド内のキーであり、テキストエディターの割り当てや保存の Ctrl+S は変わりません。

`/resume` では、入力するとタイトルと会話テキストを検索し、各行の下に一致したテキストを表示します。Ctrl+D で確認後に選択中のセッションを削除します。

確認画面（承認など）は未選択で始まります。矢印キーで選ぶまで Enter は何もしないので、表示された瞬間にメッセージへ入力したキーが誤って回答になることはありません。「はい」と即答するキーはデフォルトではありません（`dialog.yes` は割り当てない限り未設定です）。承認で Esc を押すと呼び出しを拒否し、ターンを停止します。

| アクション | デフォルトのキー | 動作 |
| --- | --- | --- |
| `dialog.up` | `up`, `shift+tab` | 前の選択肢を選びます |
| `dialog.down` | `down`, `tab` | 次の選択肢を選びます |
| `dialog.choose` | `enter` | 選択中の項目を選ぶか、入力を送信します |
| `dialog.cancel` | `escape`, `ctrl+c` | ダイアログをキャンセルします |
| `dialog.yes` | なし | 確認に即座に「はい」と回答します |
| `dialog.no` | `n` | 確認に「いいえ」と回答します |
| `dialog.toggle` | `space` | 複数選択で、選択中の項目のチェックを付け外しします |
| `dialog.prev-question` | `left` | 複数の質問で、前の質問へ戻ります |
| `dialog.next-question` | `right` | 複数の質問で、まだ未回答の最初の質問まで次へ進みます |

### 拡張機能のビュー

コマンドで開く全画面ビューは、次のホストアクションを使います。最小限のフッターを持つビューも含め、ヒントには現在の割り当てを表示します。空の一覧はアクションの割り当てを解除します。隠れた Esc や Ctrl+C のフォールバックはないので、ビューを終了するキーを必ず残してください。

| アクション | デフォルトのキー | 動作 |
| --- | --- | --- |
| `view.focus` | `f6`, `ctrl+tab` | デフォルトのビューも含め、ビューと入力欄の間でフォーカスを切り替えます。所有する会話のネイティブフォーカスからメインへ戻ります。Ctrl+Tab は端末が通知する場合に使える別名です |
| `view.back` | `escape` | アクティブなテキスト欄から抜け、1 ページ戻るか、ルートページを閉じます。ビューのプロンプトをキャンセルします |
| `view.close` | `q`, `ctrl+c` | 入れ子のページも含め、ビュー全体を閉じます |
| `view.scroll-up` | `up` | ビューのテキストを 1 行上へスクロールします |
| `view.scroll-down` | `down` | ビューのテキストを 1 行下へスクロールします |

ビューは後述の共通 `scroll.*` アクションも使います。デフォルトでは Shift+↑/↓、PgUp/PgDn、Home/End です。再割り当てや解除は会話記録とビューの両方に影響します。別の `view.scroll-up` / `view.scroll-down` アクションにより、矢印キーでプロンプト履歴を呼び出す動作を変えずに、ビュー内では通常の矢印を使えます。ビューの行単位スクロールをすべて無効にするには、ビューと共通の両方の行スクロールアクションの割り当てを解除してください。

端末が F6 を通知する場合、F6（`view.focus`）は、デフォルトのビューを含む、すべての拡張ビューと入力欄の間でフォーカスを切り替えます。端末が通知する場合は Ctrl+Tab も同じアクションの別名です。Windows Terminal は Ctrl+Tab を横取りし、従来の端末は通常の Tab として通知する場合があります。F6 はこれらの Ctrl+Tab の問題を避けられますが、VS Code の統合ターミナルでは `terminal.integrated.commandsToSkipShell` に `workbench.action.focusNextPart` が含まれているため、デフォルトで F6 が横取りされます。VS Code の設定で `terminal.integrated.commandsToSkipShell` に `"-workbench.action.focusNextPart"` を追加するか、Amira の `view.focus` を端末が通知するキーに再割り当てしてください。Shift+Tab 単独は `view.focus` に割り当てられません。権限モードの切り替えとビュー内の逆方向の移動に予約されています。デフォルトのビューは引き続き Tab も使え、ヒントは F6 を表示せず `tab→input/view` のままです。`ViewDefinition.needsTab: true` を宣言したビューは Tab と Shift+Tab をウィジェットやビューの操作に使い、デフォルトのフォーカスヒントは Ctrl+Tab ではなく `f6→input/view` を表示します。サブエージェントのビューアーはこの設定を使うため、Tab/Shift+Tab は引き続き子を切り替えます。ホストのフォーカス切り替えは Shift+Tab を使いません。

ビューにフォーカスがあるとき、`/` は入力欄へ移動して `/` を入力し、コマンドの入力を開始します。`i` は入力欄へ移動しますが、`i` は入力しません。ビューが処理する表示可能なキー（`m`、`p`、`s` など）はそのまま使えます。それ以外の未処理の表示可能なキーは、入力欄へ移動してその文字を入力します。操作中のビュー内テキスト欄やプロンプトは、`/` と `i` も含め、引き続き入力を受け取ります。履歴検索中は、Esc が先に検索をキャンセルして下書きを戻します。入力欄が空なら、次の Esc でビューや選択可能なドックへフォーカスを戻します。検索中でなければ、空の入力欄で Esc を押すと直ちにフォーカスを戻します。テキストがある場合、Esc は従来の動作を維持し、フォーカス切り替えには使いません。ビュー内の Esc は従来どおり戻るか閉じます。入力欄をクリックすると入力欄にフォーカスします。拡張ビューの隣では、フォーカス中の枠はアクセント色の役割、非フォーカス時の枠は控えめな色を使います。宣言的なビューの選択行は、ビューが非アクティブな間は薄く表示します。

ドックは入力欄にフォーカスした状態で開きます。選択可能な内容があれば F6 でドックへ移動します（Ctrl+Tab は端末が通知する場合に使える別名です）。`needsTab: true` でなければ Tab も使えます。入力欄が空なら、全画面ビューと同様に、Esc は選択可能なドックへ戻ります。テキストがある場合、Esc は従来どおりドックを閉じ、下書きを保持します。読み取り専用のドックは、フォーカスを取らず従来のスクロール動作を維持し、Esc で閉じます。ダイアログの表示中は、ドック上のホイールスクロールだけが可能で、クリックしてもドックへのフォーカス移動や内容の選択は行いません。

拡張機能が定義したショートカットはその定義を維持し、スクロールより優先されます。`needsTab: true` のウィジェットを使うビューでは、Tab/Shift+Tab はウィジェット間を移動します。矢印と Enter は引き続きウィジェット間の移動や操作を行い、スクロールアクションはフォーカス中のスクロール可能な領域に適用します。フォーカス中のテキスト欄は、`q` や、戻る・閉じるに割り当てた表示可能な文字も含め、表示可能な文字を処理します。表示可能な文字でない閉じるキー（Ctrl+C など）は、テキスト欄やプロンプトからもビューを閉じます。確認画面では、表示可能な文字のキーはビューを閉じずに確認へ回答します。

### 会話記録（全画面モード）

Amira が会話を保持し、スクロールを処理します。これらのキーは入力欄より先に会話記録へ作用します。Home、End、通常の文字は、入力が空のときだけ会話記録へ作用し、入力がある場合は入力欄が使います。マウスホイールは 1 目盛りで 3 行スクロールし、ドラッグはテキストを選択します（[テキスト選択](#テキスト選択)を参照）。クリックは他の動作をしないので、キーボードの入力先は入力欄のままです。ブロックはキーボード（`select.start`）で選択します。

表示は最新の出力を追いかけます。上へスクロールすると、会話が増えてもその位置を維持し、その下の行に下方の行数を表示します（`↓ 124 rows below`、追加の出力があると `↓ new output · 124 rows below`）。末尾までスクロールするか End を押すと、再び追従します。

| アクション | デフォルトのキー | 動作 |
| --- | --- | --- |
| `scroll.up` | `shift+up` | 1 行上へスクロールします |
| `scroll.down` | `shift+down` | 1 行下へスクロールします |
| `scroll.page-up` | `pageup` | 1 ページ上へスクロールします |
| `scroll.page-down` | `pagedown` | 1 ページ下へスクロールします |
| `scroll.top` | `ctrl+home`, `home`, `alt+home`（VS Code では `alt+home` が先頭） | 会話の先頭へ移動します |
| `scroll.bottom` | `ctrl+end`, `end`, `alt+end`（VS Code では `alt+end` が先頭） | 末尾へ移動し、再び追従します |
| `select.start` | `ctrl+up`, `alt+up`（VS Code では `alt+up` が先頭） | 最新のブロック（メッセージ、回答、ツール呼び出し、通知）を選びます |
| `find` | `ctrl+f`, `alt+f`（VS Code では `alt+f` が先頭） | 検索バーを開きます |

### ブロック選択

ブロックを選択中は最初の列に印を付けます（空白なら `▌`、文字があれば反転表示です。幅は維持するので位置は動きません）。入力欄の上の行に種類と位置を `reply 3 of 9` のように示します。一部が画面内にあるブロックを選んでもスクロールしません。文字入力や貼り付けは入力欄へ戻ります。選択が使わないキー（Ctrl+C、Ctrl+O、Ctrl+D）は、入力欄での動作を行います。

`select.open` はコードブロックを含む回答に入り、最初のコードブロックを選択します。`↑`/`↓` で回答内のコードブロックを移動し、`select.copy` で選択中のコードを枠なしの元の形でコピーし、`select.back` または Esc で回答全体へ戻ります。折りたたまれた回答は先に展開し、コード全体を表示します。サブエージェントを持つツール呼び出し（またはバックグラウンドのサブエージェントのブロック）では、`select.open` は実行中のサブエージェント、なければ最新のサブエージェントのビューアーを開きます。そこで `←`/`→` で切り替えます。

| アクション | デフォルトのキー | 動作 |
| --- | --- | --- |
| `select.prev` | `up`, `ctrl+up`, `alt+up`, `k` | 前のブロックを選びます |
| `select.next` | `down`, `ctrl+down`, `alt+down`, `j` | 次のブロックを選びます |
| `select.toggle` | `enter`, `space` | ツール呼び出しの出力（サブエージェントも含みます）、長いコードブロック、回答の `<details>` を折りたたむか展開します |
| `select.copy` | `y`, `c` | ブロック（または選択中のコードブロック）をクリップボードへコピーします |
| `select.open` | `right`, `o` | 回答のコードブロックに入るか、呼び出しのサブエージェントのビューアーを開きます |
| `select.back` | `left` | コードブロックから回答全体へ戻ります |
| `select.exit` | `escape` | 選択を終了します（コードブロック内では回答へ戻ります） |

`tool-output`（Ctrl+O）は要約表示と完全表示を切り替え、折りたたみ表示からは要約表示に戻ります。`/verbose collapsed` は折りたたみ表示を選び、引数なしの `/verbose` は要約 → 完全 → 折りたたみの順に切り替えます。完全表示では思考テキストも表示します。実行中の思考と保持された思考を表示します。思考のヒントは、次の操作でテキストを表示する場合だけ現れ、現在の割り当てを示します。手動で折りたたみ・展開したブロックは、それぞれの表示レベルを維持します。

### テキスト選択

全画面モードでは Amira がマウスでのテキスト選択を処理します。左ボタンでドラッグすると、行やブロックをまたいで選択を表示します。ボタンを離すとクリップボードへコピーし（OSC 52。[コピー](#コピー)を参照）、ヒント行にコピーした文字数を表示します。ダブルクリックは単語（文字、数字、パスや URL の構成文字）、トリプルクリックは行を選びます。会話記録の最終行より下、または下方から移動して最上行で押し続けると、ドラッグで会話記録をスクロールします。押し続けるほど速くなります。

コピーするのは表示されたテキストで、会話記録独自の印は含みません。メッセージ前の `›`、回答のインデント、引用の縦線、ツール呼び出しやサブエージェントの `●`、`└`、ツリー記号、コードブロックの枠は除きます。コードは元の形でコピーします。インデントを保持し、複数行に折り返された 1 行は 1 行に戻し、行全体を選択した場合はタブも保持します。画像は代替テキストとしてコピーします。他のテキストは画面の折り返しに従って行ごとにコピーし、箇条書き記号とリンクは表示どおりになります。非常に大きな選択（約 100,000 文字を超える場合）は端末が受け取れる量を超える可能性があり、その旨を通知します。

会話が下で進行しても、スクロール中でも選択は保持されます。クリックすると解除します。メッセージ送信、選択範囲内のブロックの変更（ツール呼び出しの完了、折りたたみ、出力レベルの変更）、サイズ変更（テキストの配置が変わります）でも解除します。文字入力は引き続き入力欄へ送られます。

| アクション | デフォルトのキー | 動作 |
| --- | --- | --- |
| `text.clear` | `escape` | 選択を解除します。テキスト選択中の Esc は、ダイアログへの回答を除き、一覧・検索バー・履歴検索の終了やターン停止より先にこれを行います |

Shift を押しながらドラッグすると、代わりに端末側の選択を使います（[コピー](#コピー)を参照）。OSC 52 がクリップボードに届かない場合の代替手段です。

### 検索

検索バーは入力に応じて会話記録全体のテキストを検索し、会話が進むと再検索します。入力に大文字がない限り、大文字と小文字を区別しません。折り返されたテキストは 1 行として検索します（表示上の改行はスペースとして扱います）。そのため一致結果は幅に依存しません。一致箇所を強調し、現在の一致には下線も付けます。バーは全件中の何件目かを表示し、最新の一致から始めます。`/clear` と `/resume` は会話記録を新しくします。検索、コピー、終了時の出力は、表示中のセッションだけを対象にします。

| アクション | デフォルトのキー | 動作 |
| --- | --- | --- |
| `find.next` | `enter`, `up`, `f3` | 上方の次の一致（古いもの）へ移動します |
| `find.prev` | `shift+enter`, `down`, `shift+f3` | 下方の次の一致（新しいもの）へ移動します |
| `find.close` | `escape`, `ctrl+c`, `ctrl+g` | 一致箇所に留まったまま検索バーを閉じます |

### コピー

コピー用のキーは OSC 52 でテキストをクリップボードへ送ります。Windows Terminal、VS Code、iTerm2、kitty、WezTerm などが対応しています（tmux は `set-clipboard on` が必要です）。届いたかどうかを Amira が知る方法はありません。全画面モードではマウスイベントの通知が有効になり、[テキスト選択](#テキスト選択)のとおりドラッグで選択します。端末側の選択を使うには Shift を押しながらドラッグしてください（Windows Terminal、Windows と Linux の VS Code、xterm）。macOS の VS Code では Option を押すか、`terminal.integrated.macOptionClickForcesSelection` を設定します。マウスによる貼り付けも同様です。Windows Terminal では Shift を押しながら右クリック（Linux の端末では Shift+中クリック）するか、Ctrl+V を押します。そのボタンのクリックが Amira に届いた場合は、この方法を通知します。

VS Code は Ctrl+F、Ctrl+Home、Ctrl+End、Ctrl+↑↓ を自身の端末操作に使います（`terminal.integrated.commandsToSkipShell` に含まれます）。そのため Alt+F、Alt+Home、Alt+End、Alt+↑ を先頭にし、キーリファレンス（`?`）でも先に表示します。

入力欄内の編集キー（矢印、Home/End、Ctrl+A/Ctrl+E、単語移動と削除）、`/agents` 一覧のキー（`p` で選択中のサブエージェントを出力）とビューアーのキー（←/→ と Tab で切り替え、`x` で停止、`p` で閉じて表示中のスナップショットを出力、`q`/Esc で閉じる）、`/jobs` 一覧のキー（`x` で選択中のジョブを停止、`p` で出力）とジョブ表示のキー（`x` で確認後に停止、`q`/Esc で閉じる）は、現在は固定です。

## 端末の設定

これらはユーザーまたはプロジェクトの `settings.json` の `tui` に置きます（`.amira/settings.json` が優先されます）。

| 設定 | デフォルト値 | 動作 |
| --- | --- | --- |
| `tui.mode` | `"fullscreen"` | 非推奨で、無視されます。UI は常に代替画面の全画面で動作します。1 リリースの間、`"inline"` と `--inline` は `inline mode was removed; running fullscreen. Use -p for plain output.` と通知します。`--fullscreen` は受け付けますが、動作を変更しません。現在のプロンプトが画面外にスクロールするとヘッダーの下に固定表示します。再開した履歴のプロンプトは固定表示しません。 |
| `tui.margin` | `3` | 左右余白をセル単位で指定します（整数 0〜12）。狭い端末では、可能なら内容の幅を最低 60 列確保するよう縮めます。これと `tui.marginRows` を `0` にすると端まで出力します |
| `tui.marginRows` | `1` | 全画面モードでヘッダー上とキーヒント行の下に置く空行です（整数 0〜2）。端末が 24 行未満なら省略します |
| `tui.theme` | `"auto"` | [テーマ名](themes.md)、または端末の背景に合わせる `"auto"`（不明ならダーク）を指定します。`"dark"` と `"light"` は Amira の配色を明示的に選び、`"terminal"` は端末自身の ANSI 色を使います |
| `tui.themeVariant` | `"auto"` | 名前付きテーマの表示形式です。`"auto"` は端末の背景に合わせ、`"dark"` または `"light"` はその形式を強制します。対応するバリアントがなければ、その形式の Amira のデフォルト配色を使います |
| `tui.colorDepth` | `"auto"` | 色深度です。`"auto"` は端末の対応状況を検出し、`"truecolor"`、`"256"`、`"16"` はそれを上書きします。`"256"` と `"16"` は数値でなく文字列を使ってください |
| `tui.title` | `true` | セッションタイトルがある場合、端末タイトルを `Amira · <folder> · <session title> ⎇ <branch>` に設定し、ターン実行中は `●` を付けます。終了時に前のタイトルへ戻します。タイトルバーはシステムのフォントで描画するため `⎇` を安全に使えますが、入力欄の枠内の状態表示では省きます（Cascadia Code と Mono にこの文字がありません） |
| `tui.progress` | `true` | ターン実行中はタブとタスクバーに処理中の表示を出し、ダイアログの回答待ちは一時停止の表示にします（OSC 9;4：Windows Terminal、ConEmu、VS Code、Ghostty） |
| `tui.bell` | `true` | 端末がバックグラウンドにあるとき、ターン終了やダイアログ開始でベルを鳴らします。端末がフォーカスを通知しない場合は、15 秒以上のターンの後だけ鳴らします |
| `tui.reflow` | `"auto"` | 非推奨で無視されます。全画面モードは現在の端末の幅で会話を描画し直します |
| `tui.submitWhileWorking` | `"steer"` | ターン実行中の `submit`（Enter）の動作です。`"steer"` は実行中のターンへメッセージを送り、`"queue"` はターン後に送ります。`queue` キーはもう一方を行い、ヒント行に示します（`Enter queue · Ctrl+Q steer`）。スラッシュコマンドはどちらでも直ちに実行します |
| `tui.images` | `"auto"` | 任意の [`images`](https://github.com/CAMB-dev/amira-extensions/tree/main/extensions/images/README.md) 拡張機能をインストールすると、回答内で独立した行にある画像を描画します（`amira ext install images`。ローカルファイルと、web_fetch のプライベートネットワーク保護を適用した http(s) URL を最大 10 MB まで読みます）。`"auto"` は端末が対応を通知した場合に表示します。Windows Terminal 1.22+（Sixel）、`terminal.integrated.enableImages` を有効にした VS Code、iTerm2、WezTerm、kitty、Ghostty が対象です。`"on"` は常に表示し、`"off"` は表示しません。それ以外の場合、画像処理が失敗した場合、または 3 秒を超えた場合は、画像へのリンク付きの `🖼` と代替テキストを表示します |
| `tui.shellOutputLines` | `3` | 成功したシェルコマンドの結果の下に表示する出力末尾の行数です。実行中の表示にも同じ行数を使います。`0` は表示しません。失敗したコマンドは出力の先頭と末尾を表示し、ツール出力レベル `full`（Ctrl+O）では全体を表示します |
