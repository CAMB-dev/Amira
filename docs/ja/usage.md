# Amira の使い方

[English](../usage.md) · [简体中文](../zh/usage.md) · [ドキュメント](../../README.ja.md)

作業対象のディレクトリで `amira` を実行します。位置引数のプロンプトが最初のメッセージになり、`--cwd` で別の作業ディレクトリを指定できます。プロバイダーの設定については[はじめに](getting-started.md)を参照してください。

## 推論の強度

対話モードでは `amira --thinking high`、print モードでは `amira -p --thinking xhigh "Explain this repository"` を使います。指定できるレベルは `low`、`medium`、`high`、`xhigh`、`max` です。

セッション中に `/thinking` を実行すると、この 5 つのレベルと `default`（強度を送信しません）の選択画面が開きます。`/thinking high` で直接指定したり、`/thinking default` でサーバーのデフォルト値を使ったりできます。この変更は Amira が終了するまで有効で、設定ファイルには書き込みません。現在のモデルと同様に、`/clear`、`/resume`、巻き戻し、フォークで切り替えた先の会話にも引き継がれます。優先順位は、セッションの実行時の選択 > `--thinking` > `providers.<id>.models[].thinking` > [設定](settings.md)のトップレベルの `thinking` です。`default` を明示的に選ぶと、優先順位の低い 3 つの指定はすべて抑制されます。フラグや設定の値に戻るわけではありません。選択も強度の設定もない場合も、リクエストに強度は含まれません。

対話型の `/model` 選択画面で思考に対応したモデルを選ぶと、続いて同じ強度を選べます。その段階で Esc を押すと、選択したモデルは維持され、強度は変更されません。強度を受け取るのは `caps.thinking` を持つモデルだけです。ステータスバーではモデル名の横に表示され、`/status` でも対応モデルに限って表示されます。思考に非対応のモデルへ切り替えると、選択は保持したまま強度の表示が消えます。サブエージェントは親の選択した強度を引き継ぎますが、タイトル生成と圧縮にはデフォルト値が使われます。

Responses と Anthropic の adaptive モードはレベルをそのまま送信します。Anthropic の budget モードでは `xhigh` を 32,768 トークンに対応させます。`max` の 64,000 より少なく、回答用の余地を残すよう上限を調整します。Gemini は `xhigh` を `high` と同じように扱い、Gemini 2.5 Pro 用の大きな `max` 予算を維持します。Chat Completions は現在、推論パラメーターを送信しません。

## 高速モード

`/fast` は要求する高速モードの設定を切り替えます。`/fast on` と `/fast off` で明示的に指定できます。`/fast status` は、要求、現在のモデル/プロバイダーへの適用状況、最後の回答の実際のサービス層または Claude の速度（例：`priority`、`default`、`fast`、`standard`）を表示し、設定は変更しません。非対応のモデルでも要求を保持し、適用できない理由を表示します。

高速モードは提供速度を上げるための要求であり、モデルや思考の強度は変えません。プリセットはエンドポイントとモデルによって異なります。

| プロバイダー | プリセットと制限 |
| --- | --- |
| Claude 公式 API | 対応する Claude Opus モデルで Anthropic の `speed: "fast"`（リサーチプレビュー）を使います。高速モードには標準モードとは別のレート制限があります。互換ゲートウェイ、Bedrock、Vertex、Foundry、Claude Platform on AWS では自動的に有効になりません。 |
| OpenAI | Chat Completions と Responses で `service_tier: "priority"` を要求します。利用可否はモデルとアカウントに依存します。Priority は同じモデルの標準モードとレート制限を共有します。レスポンスは実際の層を報告し、ダウングレード後は標準層になる場合があります。 |
| xAI | テキストのみのリクエストで `priority` を要求します。画像を含む場合は適用しません。優先処理の容量が不足すると `default` にフォールバックできます。 |
| Google Gemini | 対応モデルで `priority` を要求します。レスポンスヘッダー `x-gemini-service-tier` が実際の層を報告します。容量超過時はエラーなしで標準層にダウングレードできます。 |
| OpenRouter | OpenAI、Anthropic 高速モード、Google Vertex/AI Studio、xAI のカテゴリーのうち、選択された対応モデルだけが対象です。利用可否と料金はモデルと上流のエンドポイントに依存し、カタログとの一致だけでは対応を保証しません。 |
| DeepInfra | 優先処理の対応タグがあるモデルだけが対象です。対応を確認してモデルの `fast` サービス層設定を指定してください。非対応の層は通知なしで標準速度になる場合があります。 |
| DeepSeek と Moonshot/Kimi の公式 API | DeepSeek に高速リクエスト用フラグはありません。Kimi では別の `*-highspeed` モデルに切り替えてください。`/fast` はモデルを切り替えません。 |

料金と容量制限はプロバイダーによって異なります。リクエストが標準モードにフォールバックしても設定はオフになりません。設定を変更するとプロンプトキャッシュが無効になる場合があります。`/cost` はモデルごとの実際の報告値を高速と標準の行に分け、要求だけで高速料金と判断しません。追加料金が不明な場合、`/fast status` は警告し、`/cost` は対象金額と合計を**標準料金による見積もり**と表示し、**追加料金が不明**であることを明記します。正確な高速料金ではありません。任意の `cost.fast` を設定する前に、プロバイダーの最新料金を確認してください。

デフォルトはオフです。[設定](settings.md#高速モード)に `"fastMode": true` を指定すると、起動時に高速モードを要求します。同節にはエンドポイント/モデルの上書き例もあります。対話中の `/fast` による実際の変更はユーザー設定と、許可されていればプロジェクトの `settings.local.json` に保存されます。状態の確認や現在と同じ値の選択では保存しません。print モード、RPC、拡張機能による変更も保存しません。サブエージェントは設定を引き継ぎますが、対応する場合だけ適用します。

## 端末モードと会話記録

```sh
amira --fullscreen
amira --inline
amira --cwd /path/to/project "Explain this repository"
```

デフォルトでは全画面モードです。Amira は代替画面に会話記録を保持し、スクロールと検索を自ら処理し、終了時に表示中のセッションを通常の端末画面へ出力します。インラインモードでは、完了したメッセージとツール呼び出しが端末のスクロールバックに残ります。端末側のスクロール、検索、テキスト選択を使ってください。SSH や tmux での利用に便利です。これらのフラグは[設定](settings.md)の `tui.mode` より優先されます。

会話記録には、送信したメッセージ、ストリーミングされた回答、モデルが提供する思考内容、ツールの実行状況、質問、通知が含まれます。全画面モードでは PgUp/PgDn でスクロールし、入力が空のときに End を押すと最新の出力へ戻ります。Ctrl+F で会話記録を検索します。Ctrl+Up でブロックを選択し、↑/↓ でブロック間を移動、Enter で折りたたみ・展開、`y` でコピーします。端末によっては[キー割り当て](keybindings.md)に記載した代替キーが必要です。

どちらのモードでも Ctrl+O でツール出力の要約表示と完全表示を切り替えます。折りたたみ表示からは要約表示に戻ります。`/verbose collapsed` は折りたたみ表示を選択し、引数なしの `/verbose` は引き続き 3 段階を順番に切り替えます。Alt+C で最後の回答を Markdown としてコピーします。全画面モードではドラッグでテキストを選択してコピーでき、Shift+ドラッグは端末側の選択を使います。入力が空のときに `?` を押すと、現在のキー割り当てを確認できます。

## 送信、実行中の指示、キューへの追加

待機中は Enter でメッセージを送信します。ターンの実行中は、通常 Enter で**実行中の指示**を送ります。実行中のツールを中断せず、次のモデルリクエストの前にメッセージをエージェントへ届けます。Alt+Enter は現在のターン終了後に送るメッセージをキューに追加します。Windows Terminal が Alt+Enter を予約している場合は、もう一つの割り当てである Ctrl+Q を使えます。`tui.submitWhileWorking` を `"queue"` にすると、この 2 つの動作が入れ替わります。

対応する端末では Shift+Enter で改行を挿入でき、代わりに Ctrl+Enter も使えます。`/` でコマンド、`$` でスキル、`@` に続けてパスの一部を入力するとファイル補完を利用できます。編集、補完、履歴操作については[キー割り当て](keybindings.md)を参照してください。

Esc は現在のターンを停止します。`/ext install` などのスラッシュコマンドが実行中なら、先にそのコマンドをキャンセルし、入力中の下書きを保持します。実行中の指示やキュー内のメッセージが待機している場合は、入力順にまとめて一度に送信します。バックグラウンドのサブエージェントは動き続けます。停止方法は[サブエージェント](subagents.md)を参照してください。Ctrl+C も、実行中のコマンドがあればまずキャンセルし、なければターンを停止し、実行中でなければ空でない入力を消去し、それもなければ終了します。`/quit` でも終了できます。

## ステップ数の上限

メインエージェントは、デフォルトでは 1 ターンに最大 500 回モデルを呼び出せます。[設定](settings.md#一般)の `agent.maxSteps` に 0 以上の整数を指定してください。`0` はステップ数を無制限にします。`--max-steps <n>` は対話モードと print モードの両方で、1 回の実行に限って設定を上書きし、保存はしません。

この上限はメインエージェントだけに適用され、サブエージェントには引き継がれません。ステップ数の上限をなくしても、中断、予算の上限、コンテキストエラーによってターンが停止する動作は変わりません。

## 画像

どちらの端末モードでも、メッセージに PNG、JPEG、GIF、WebP 画像を添付できます。

- **パスを貼り付けるかドロップします。** 既存の画像ファイルのパスだけを貼り付けると、画像が添付されます。絶対パス、作業ディレクトリからの相対パス、スペースを含む場合の引用符付きパス、macOS や Linux の端末がドロップ時に生成するスペースをバックスラッシュでエスケープしたパス、`file://` URI に対応しています。文章や他のファイルなど、それ以外の内容はテキストとして貼り付けます。添付できない画像もテキストになり、理由を通知します。
- **`@` のファイル一覧で選びます。** 画像は添付され、他のファイルは `@path` の参照のままになります。
- **Alt+V でクリップボードから貼り付けます。** アクションは `paste.image` です。他のキーは[キー割り当て](keybindings.md)を参照してください。クリップボードにテキストがあれば、そちらを優先します。Windows では PowerShell、macOS では `osascript`（インストール済みなら `pngpaste`）、Linux では `wl-paste` または `xclip` を使います。利用できなければ不足しているものを通知しますが、パスによる添付は引き続き使えます。

添付は、入力欄と送信済みメッセージで `[image 1: screen.png 120 KB]` のような 1 つのプレースホルダーとして表示されます。Backspace や Delete で全体を削除でき、元に戻す操作、切り取り、ヤンクでも保持されます。外部エディター（Ctrl+G）でメッセージを編集する前に添付を削除してください。画像を含むメッセージは、スラッシュコマンドやスキルとして実行されません。

1 つのメッセージに含められる画像は**合計 5 MB** までです。送信には画像に対応したモデルが必要です。非対応の場合は警告が表示され、メッセージは入力欄に残ります。画像はセッションファイル内に base64 形式で保存されるので、再開時に元のファイルは不要です。画像付きのプロンプトは実行中に ↑ で呼び出せますが、プロジェクトのプロンプト履歴ファイルには書き込まれません。

## ツールと承認

同梱ツールは、ファイルの読み取り、検索、作成、編集、シェルコマンドの実行、Web 検索、作業の委任に対応しています。利用可能なツールはプラットフォーム、モデル、読み込んだ拡張機能によって異なります。`/tools` で現在のツールを一覧表示し、`/tools disable <name>` と `/tools enable <name>` でこのセッションでの利用可否を変更します。`--disable-tools` は起動時にカンマ区切りの一覧を指定します。永続的な設定については[設定](settings.md)と[拡張機能](extensions.md)を参照してください。

ファイルの変更には 2 種類の編集ツールがあります。`edit` は 1 つのファイル内で完全一致するテキストを置換します。`apply_patch` は Codex 形式（`*** Begin Patch` … `*** End Patch`）のパッチを受け取り、複数ファイルの追加、削除、更新、移動を一度に行えます。書き込み前にすべてのハンクを検証し、書き込みが失敗したら、それまでに書き込んだ内容をロールバックします。プロバイダー設定で変更しない限り、各モデルには `edit` を提供します。[編集ツール](providers.md#編集ツール)を参照してください。`write` は常に利用できます。`/tools` は現在のモデルが使わないツールを理由付きで無効と表示し、`/tools enable` では有効にできません。代わりに設定を変更してください。

`grep` と `glob` は Git と同じ対象を除外します。`.git`、`node_modules`、`.gitignore`、`.git/info/exclude`、グローバルの除外ファイルで除外したファイル、別のリポジトリやリンクされた worktree を含むディレクトリ（チェックアウト内の `.claude/worktrees/*` など）が対象です。検索対象リポジトリのサブモジュールは検索されます。明示的に渡したパスは、それ自体が除外対象でも検索します。作業ディレクトリの外にある結果は、`[outside working directory]` を付けた絶対パスで表示します。

承認要求は[権限ポリシー](#権限)や拡張機能から発生します。これらはツール呼び出しをブロックしたり、実行前の承認を求めたりできます。要求にはツール、理由（要求を発生させたモードやルールを含みます）、プレビューまたは引数が表示されます。矢印キーで選択して Enter を押してください。確認画面は未選択の状態で始まります。Esc は呼び出しを拒否し、ターンを停止します。

`Don't ask again` が提示された場合、それを選ぶと、**表示された同じ理由に限り**、セッションの残りの間そのツールを許可します。永続的な権限としては保存されません。サブエージェントの権限に関する質問は親ではなく、あなたに届きます。拡張機能がサブエージェントに対して出す質問は、引き続き親エージェントのモデルが判断します。print モードではダイアログに回答できないので、承認要求は拒否され、質問はキャンセルされます。RPC クライアントは UI 要求に明示的に回答する必要があります。RPC クライアントが stdin を閉じた後は、承認は拒否されます。

## 権限

権限モードは、モデルが確認なしで何を実行できるかを決めます。サブエージェントを含むセッション全体に適用されます。

| モード | 動作 |
| --- | --- |
| `auto`（デフォルト） | ルールや保護されたファイルで制限されない限り、確認なしですべて実行します |
| `edits` | 確認なしでファイルを変更します。`allow` ルールに含まれないシェルコマンドは事前に確認します |
| `plan` | 読み取り専用で、ファイル変更もシェルコマンドも実行しません。MCP ツールなど、読み取り専用と判定できないツールは事前に確認します |

UI で Shift+Tab を押すと、`auto`、`edits`、`plan` を順に切り替えます。`auto` 以外のモードは、入力欄の枠内でモデル名の横に表示されます。`--permission-mode <mode>` または設定の `"permissions": {"mode": "edits"}` で起動時のモードを選べます。現在、Amira はコマンドが読み取りだけを行うと証明できないため、plan モードではすべてのシェルコマンドをブロックします。

コマンドルールはコマンドの単語に基づき、シェルコマンドを許可、確認、拒否します。

```json
{
  "permissions": {
    "mode": "edits",
    "rules": [
      { "command": ["git", "status"], "decision": "allow" },
      { "command": ["git", "push"], "decision": "ask", "reason": "Review what goes out" },
      { "command": ["rm", "-rf"], "decision": "deny" }
    ]
  }
}
```

ルールは文字列そのものではなく、コマンドの単語（argv）に一致します。`git status --short` は `["git", "status"]` に一致しますが、`git statusx` は一致しません。`ask` と `deny` のルールでは、コマンド名がパスや Windows の拡張子付き（`/usr/bin/git`、`git.exe`）でも一致し、PowerShell の組み込みエイリアス（`rm`、`del`、`Remove-Item` は同じコマンドです）でも一致します。指定した単語の間に別の単語がある場合（`git -C repo push` は `["git", "push"]` に一致します）も一致し、大文字と小文字を区別しません。`allow` ルールはコマンドの先頭に完全一致する必要があります。また、ルール自体がパスを指定しない限り、パスなしのコマンド名にのみ一致します（`x/git status` は `git status` ではありません）。複数のルールが一致した場合は `deny` > `ask` > `allow` の順に優先されます。`allow` は「確認しない」という意味にすぎず、plan モードやファイル保護を解除しません。

`&&`、`||`、`;`、`|`、改行でつながれたコマンドは分割し、各部分を検査します。単語ごとに検査できないコマンドは、代わりに確認を求めます。これには `$(...)` やバッククォートによる置換、変数、ファイルへのリダイレクト、ヒアドキュメントやヒアストリング、グループ化、ファイル名パターン（`*`、`?`、`[...]`）、他のコマンドを実行するラッパー（`eval`、`sudo`、`xargs`、`bash -c`、`Invoke-Expression`、`Start-Process`、インタープリター）、エイリアスを定義するコマンド（`alias`、`Set-Alias`、`git -c`、`git config alias.*`）、スクリプトが含まれます。`auto` モードでは、`ask` や `deny` のルールがなければ、これらも確認なしで実行します。コマンドは実行するシェルの解釈に従って読み取ります。bash または PowerShell が対象で、Windows で `bash` ツールが PowerShell にフォールバックする場合も含みます。

シェルコマンドは作業ディレクトリで開始するため、別のディレクトリが必要なときだけ `cd` を使ってください。Bash はフォアグラウンドとバックグラウンドのコマンドを `pipefail` 付きで実行するので、パイプラインの構成要素が失敗すると非ゼロの終了ステータスを維持します。`bun test | tail` はテストが失敗すれば失敗します。最後のコマンドが成功し、それより前のコマンドが成功または SIGPIPE（141）による終了だけであったパイプライン（`git log | head` など）は、成功として扱います。他の非ゼロのパイプラインステータスは失敗のままです。変更されるのはコマンドの最終ステータスだけで、コマンド内部ではそのパイプラインは失敗のままなので、続く `&&` は実行されません（`git log | head && echo done` は `done` を出力しません）。後続のコマンドがある場合は、`git log -n 5` などコマンド自体のオプションで出力を制限してください。PowerShell に `pipefail` オプションはありませんが、ラッパーがネイティブコマンドの失敗時の `$LASTEXITCODE` をネイティブパイプライン越しに保持します。コマンドレットのパイプラインは PowerShell の `$?` ルールに従います。

ルールは Amira に確認や拒否をさせるもので、サンドボックスではありません。拒否したプログラムへ、コピーやリンク、モデルが以前に書いたスクリプトなど別の経路で到達できる場合があります。`deny` は止めたい誤操作に使い、セキュリティ境界としては使わないでください。

ユーザーファイルのルールは常に適用されます。プロジェクトの `.amira/settings.json` や `.amira/settings.local.json` は制限を強めることしかできません。モードはユーザー設定より厳しい場合に有効になり、`ask` と `deny` のルールは適用され、`allow` のルールはプロジェクトを信頼した後にだけ適用されます（`amira ext trust`。拡張機能パッケージに必要な信頼と同じです）。プロジェクトファイルに許可されていない変更は、起動時に報告します。`--permission-mode` はすべてのファイルより優先されます。`/permissions` はモード、各ルールとその出典ファイル、省略された内容を一覧表示します。`/status` はモードとルール数を表示します。

一部のファイルは、`write`、`edit`、`apply_patch`（または書き込むパスを宣言する拡張機能ツール）で変更する前に、通常は保護対象への書き込み承認を必要とします。対象は `.amira` ディレクトリ（設定、パッケージ、ロックファイル）、Amira のユーザーディレクトリ、`.git`（フック、設定などの Git メタデータ。リンクされた worktree の Git ディレクトリも含みます）、`.gitmodules`、`core.hooksPath` が指定するディレクトリ、グローバルの Git 設定です。同じファイルを指す別の表記（大文字と小文字の違い、`../`、絶対パスや MSYS パス、リンク）も対象です。**シェルコマンドではこれらのファイルを変更できます。コマンドはまだサンドボックス内で実行されません。**

限定的な例外として、拡張機能ツールはホストから割り当てられた [`api.dataDir`](extensions.md#拡張機能の状態ディレクトリ) 内で自身の状態を管理できます。ツールは `traits.writesFiles: "paths"` を明示的に宣言し、`getWrittenPaths` を提供する必要があります。まとめられた書き込み報告のすべてのパスが、その拡張機能のディレクトリ内に安全に収まっている必要があります。内外のパスが混在する報告には部分的な免除はなく、外部のパスには通常の保護対象パスの検査を適用します。解決結果が不明または安全でない場合は承認を求めます。免除されるのは保護対象への書き込み承認だけです。plan モードは引き続き書き込みを拒否し、シェルルールや拡張機能インターセプターの承認要求は変わらず、サブエージェントにも同じポリシーが適用されます。パス報告は信頼に基づく宣言であり、サンドボックスでも、競合なしでファイルへ排他的にアクセスできる保証でもありません。

拒否された呼び出しは、理由と、あなたに確認することが次の手段である旨をモデルに伝えます。print モードや、回答可能なクライアントがいなくなった RPC では、確認が必要な操作は理由付きで拒否します。print モードは `ask_user` など UI を必要とするツールをモデルから隠します（サブエージェントも含みます）。また、システムプロンプトで非対話実行と伝えるため、モデルが自ら判断します。無人実行には `auto` モードやルールを使ってください。

## セッション、圧縮、巻き戻し

会話は自動保存され、作業ディレクトリごとに一覧表示されます。終了時には、空でないセッションを続けるためのコマンドを出力します。

| 操作 | コマンド |
| --- | --- |
| このディレクトリの最新セッションを続けます | `amira -c` または `amira --continue` |
| 保存済みセッションを選びます | `amira -r` または `amira --resume` |
| ID が分かっているセッションを再開します | `amira -r <session-id>` |
| UI なしでセッションを一覧表示します | `amira -p -r` |
| UI 内で選択・切り替えます | `/resume` または `/resume <session-id>` |
| 空の会話を開始します | `/clear` |
| 現在のセッションに名前を付けるか、名前を消去します | `/rename [title]` |
| このセッションのコピーで続けます | `/fork` |
| 以前のユーザーメッセージまで巻き戻します | `/rewind` または `/rewind <n> [--yes]` |
| UI なしで保存済みセッションを削除します | `amira sessions rm <session-id>`（別のディレクトリは `-C <dir>`） |
| 古いコンテキストを今すぐ圧縮します | `/compact` または `/compact <instructions>` |

`-c` と `-r` は併用しないでください。セッション ID は `s_` で始まります。一覧に表示された実際の ID を使ってください。`/clear` は保存される新しいセッションを開始し、以前のセッションは再開できる状態で残します。`/resume` は現在選択中のモデルを維持します。モデルが未選択なら、保存済みのモデルを使えます。トップレベルのバックグラウンドジョブは `/clear`、`/resume`、`/fork` 後も存続し、新しいセッションから一覧表示、読み取り、停止ができます。サブエージェントが所有するジョブは、そのサブエージェントの終了時に停止します。Amira の終了時にはすべてのバックグラウンドジョブを停止します。

セッションの最初のターンが成功すると、Amira はバックグラウンドでモデルに短いタイトルを依頼します（会話の言語で、最大 6 語かつ 60 文字）。`compact.model` が設定されていればそれを使い、なければ現在のモデルを使います。会話を待たせることはありません。print モードとサブエージェントはタイトルを依頼しません。リクエストの費用は `/cost` と `/status` に表示されます。`/rename` による名前は自動タイトルより常に優先されます。引数なしの `/rename` は手動の名前を消去し、最新の自動タイトルに戻します。無効にするには、ユーザー設定かプロジェクト設定で `"sessions": { "autoTitle": false }` を指定してください。タイトルはディレクトリ名とともに `/status`、`/resume`、`amira -r`、端末タイトルに表示されます。

`/resume` の選択画面に入力すると、タイトルと会話全体のユーザー・アシスタントのテキストを検索します。圧縮済みの履歴も対象です。大文字と小文字を区別しない部分文字列で照合するため、中国語や日本語にはスペースが不要です。一致したテキストは行の下に表示されます。Ctrl+D は確認後に選択中のセッションを削除します。現在のセッションは一覧に含まれません。削除すると、セッションファイル、記録済みのファイル履歴、保存したアーティファクト、そのセッションが開始したサブエージェントのセッション（さらにその子孫も）を削除します。ただし、フォークがまだ使用しているものは除きます。別の実行中の Amira プロセスがセッションを開いている場合は、メッセージを表示して削除を拒否します。クラッシュしたプロセスの所有者レコード付きリースを回収するのは、同じホストと PID ドメイン内で所有者の終了を証明できる場合だけです。古いビルドの従来形式のリースには、後述するハートビートに基づく限定的な回収が適用されます。それ以外の検証不能なリースには、オフラインでのクリーンアップが必要です。

セッションの書き込みには、`<session-file>.lock.lease-gate` の短時間だけ保持する stale-write guard（古い書き込みを防ぐガード）も使います。このガードと永続的な `<session-file>.lock` リースは、PID、一意の nonce、作成時刻、ホストと PID ドメインの識別情報を含む、バージョン付きの所有者レコードを保持します。作成、回収、解放の途中でプロセスがクラッシュした場合、次の再開または削除の試行時に自動回収するのは、**同じホストと PID ドメイン内で所有者の終了を証明できる場合だけ**です。経過時間だけでは引き継ぎを許可しません。アップグレード互換性のため、従来の PID だけのリース（または空・解析不能な単一行のリース）は、**このホストでその PID の終了を証明できる（または有効な PID がない）ことと、mtime が `SESSION_LOCK_STALE_MS`（30 秒）より古いことの両方**を満たす場合にのみ回収できます。古いビルドは `SESSION_LOCK_HEARTBEAT_MS`（10 秒）ごとに更新するので、別ホストの保持者もリースを新鮮な状態に維持します。ローカルの PID が生存している場合は、ファイルが古くても回収をブロックします。従来形式の回収にも同じゲートを使い、退避前と移動先でファイルの識別情報、内容、mtime を再確認します。変更されたリースは他の保持者を上書きせずに戻し、獲得者が必ず 1 つだけとなる所有者レコード付きリースを公開します。移動した従来形式のリースには固定パス `<session-file>.lock.legacy-stale` を使い、それ以降の獲得試行は先に排他的に復元する必要があります。このため、復元失敗や回収プロセスのクラッシュによって、生存している可能性のある保持者の権限が黙って失われることはありません。無効な所有者レコードや他の環境の所有者レコードには、この従来形式のルールを適用しません。セッションのロックはファイルシステム操作だけを使い、ネイティブローダー、libc、`flock`、FFI は不要です。各書き込みプロセスは空でない専用ガードディレクトリを初期化してからアトミックに公開し、公開が成功した場合にだけガードを獲得します。回収側は終了を証明し、正式なパスで同じ所有者であることを再確認してから、終了した所有者のガードを `<session-file>.lock.lease-gate.dead-<owner-nonce>` に改名します。この空でないクラッシュのトゥームストーン（終了した所有者のガードを隔離して保持する記録）は保持します。遅れて動く回収側が、置き換えた書き込みプロセスの解放後であっても、新しいガードをそこへ上書き移動することを防ぎます。回収は他のセッションパスをブロックしません。通常の解放では、自身の nonce を検証したガードを専用のクリーンアップパスへ移してから削除するため、クラッシュしても正式なパスに空のガードが残りません。通常の獲得・解放サイクルは補助ファイルを残さず、中断された操作や回収だけが残留物を残します。これらの保証には、全参加者がこのプロトコルを使い、ディレクトリのアトミックな改名とファイルの排他的な公開をサポートするファイルシステムが必要です。ガードパスの外部からの編集はプロトコルの対象外です。正体不明の空のガードディレクトリは上書きせず、安全側に倒して拒否します。

従来形式のリースでブロックされた場合は、古い Amira ビルドがセッションを保持しているようだと通知します。再開や削除の前にそれを終了して、再試行してください。クラッシュ後はリースが古くなるまで待ってください。使用中または検証不能なガードや、それ以外の検証不能な永続リースは、再開や削除時に「別プロセスが開いている」と断定せず、**stale-write guard** エラーを報告します。エラーは試行をブロックしたガードディレクトリやリースファイルを示します。まず再試行してください。ガードの公開前に競合した場合は、まだガードがないと明示し、削除の指示は出しません。生存中の所有者、元の所有者と区別できない再利用された PID、別のホストや PID ドメイン、証拠不足、古いまたは無効な所有者レコードは、自動回収をブロックします。ホストの証明には、ホスト名とプラットフォームに加え、Linux ではマシン ID、それが利用できなければネットワークインターフェースの識別情報を使います。Linux ではさらに同じ起動識別情報と PID 名前空間が必要です。これらが変わった場合は手動回収が必要になることがあります。**これらのセッションファイルを使用するどのホストでも Amira プロセスが動いていないことを確認してからのみ**、エラーに示された実在する `.lease-gate` ディレクトリまたは `.lock` / `.lock.legacy-stale` リースファイルを正確に指定して削除し、元のコマンド（例：`amira -r <session-id>`）を再試行してください。他の環境や従来形式のリースにはガードディレクトリがない場合があります。存在しないガードを削除してもリースは回収できません。書き込みプロセスが動いている可能性がある間は、セッションの `.jsonl` ファイル、ガード、リース、保持されているクラッシュの トゥームストーン を削除しないでください。**実行中に `.lease-gate.dead-<owner-nonce>` の トゥームストーン を削除してはいけません。** これはクラッシュした書き込みプロセスだけでなく、遅延した回収側も隔離します。クラッシュで残った `.lease-gate.pending-*`、`.lease-gate.retired-*`、`.lock.pending-*`、`.lock.stale-*` は専用の準備・クリーンアップ用の残留パスであり、書き込み権限を示すものではありません。これらと保持されたクラッシュの トゥームストーン は、同じオフライン条件を満たす場合にだけ削除できます。専用のクリーンアップコマンドは不要です。

`/fork` は現在の会話分岐を、出所を記録した `<title> (fork)` という名前の新しいセッションにコピーし、そちらへ切り替えます。以前の巻き戻しで破棄したメッセージはコピーされず、元のセッションはそのまま残ります。

自動圧縮は通常、モデルのコンテキストウィンドウの 80% に達すると開始します。最近の会話を保持しつつ、古いコンテキストを減らします。対応するプロバイダーではネイティブ圧縮を利用でき、それ以外では Amira がテキスト要約を作成します。`/compact` に指示を渡すと、必ずテキスト要約を使います。条件とオプションは[プロバイダー](providers.md)と[設定](settings.md)を参照してください。`/context` はコンテキストウィンドウの使用内訳を表示します。

全画面・インラインのどちらのモードでも、Esc を続けて 2 回押すか `/rewind` を実行すると巻き戻しの選択画面が開きます。以前のユーザーメッセージを選び、**Restore files too** または **Conversation only** を選択します。そのメッセージ以降に記録済みの変更がある場合は、デフォルトでファイル復元を選択します。画面には復元・削除するファイル数のプレビューと競合一覧が表示されます。そのメッセージとそれ以降はアクティブな会話から除かれ、プロンプトは編集・再送信のため入力欄に戻ります。選択画面で F を押すと、代わりにフォークします。新しいセッションは現在の分岐上の選択したメッセージの直前で終わり、以前の巻き戻しで破棄したメッセージはコピーされません。現在のセッションは全体を保持し、ファイルは復元しません。圧縮後も残っているメッセージだけを選べ、保存済みセッションが必要です。ポップアップ、テキスト選択、ダイアログが先に Esc を処理する場合があるので、現在のヒント行に従ってください。

`/rewind <n>` は新しい順に n 番目のユーザーメッセージの直前へ直接移動し、そのメッセージ、削るメッセージ数、ファイルの復元・削除数、競合を表示して確認を求めます。選択画面のデフォルト動作と同様に、記録済みのファイルがあれば復元し、競合があれば巻き戻し全体を拒否します。print モードや RPC クライアントが確認に回答できない場合は、セッションを変更せずに拒否します。`/rewind <n> --yes` は、適用する予定のプレビューを確認した後にのみ使ってください。数値なしの `/rewind` は選択画面が必要なため、端末 UI で利用できます。

ターンはユーザーのプロンプトから始まります。その直前へ巻き戻すと、影響する各ファイルを、そのプロンプト後の最初の記録対象の変更より前のバイト列へ復元し、その時点で存在しなかったファイルは削除します。記録対象は Amira の `write`、`edit`、`apply_patch` と、書き込むパスを宣言する拡張機能ツールだけです。同じディレクトリまたはそのサブディレクトリで動くサブエージェントのファイルツールによる書き込みも含みます。**シェルコマンド、フックから実行するフォーマッター、他のプロセス、ユーザーによる編集、別の worktree のサブエージェントは記録対象外です。** 復元前に、影響するすべてのファイルをジャーナルが想定する最後の内容と比較します。記録対象の書き込み間に外部から変更された場合も含め、少しでも不一致があると復元全体を拒否し、会話を変更しません。列挙された競合を解消するか、会話だけの巻き戻しを選んでください。巻き戻す前に、実行中のサブエージェントを停止してください。

ファイルのバイト列は、バイナリの変更前の内容も含め、セッションの JSONL 記録の隣にある `<session-id>.assets/files/` にハッシュ別で保存します。ジャーナルにはパス、変更前後のハッシュ、プロンプト、ターン、ツール呼び出しを記録します。`fileRewind.maxFileBytes`（デフォルト 10485760、10 MiB）と `fileRewind.quotaBytes`（デフォルト 268435456、セッションごとに重複を除いて 256 MiB）で保存量を制限します。変更前と変更後の内容の両方がサイズ上限内に収まる必要があります。大きすぎる新しい内容を拒否することで、将来の復元サイズも制限内に維持します。内容やジャーナル項目の保存に失敗すると、ツールの書き込みを拒否します。パスはシンボリックリンク、ジャンクション、大文字と小文字、短い名前を解決した実パスで記録するため、別の経路で到達した同じファイルを 1 つとして扱います。記録したパスが後から別の場所を指す場合（途中のディレクトリがリンクに置き換わった場合など）は競合とみなします。他のハードリンクを持つファイルはその場で復元するため、すべてのリンクで復元後のバイト列が見えます。削除されたハードリンク付きファイルは別個のファイルとして戻します。無効にするには `"fileRewind": { "enabled": false }` を設定してください。選択画面にはファイルを復元しないと表示されます。

記録済み履歴は、会話の分岐や再起動をまたいで、セッションが存続する限り保持します。`/rewind-prune` は現在のセッションの記録済みファイル履歴をすべて明示的に破棄し、保存枠を解放します。それ以前の変更は復元できなくなりますが、以降の書き込みから新しい履歴を開始します。自動削除はありません。セッションの削除（`/resume` の Ctrl+D または `amira sessions rm <id>`）は記録済みファイル履歴も削除します。記録を手動で削除する場合は、対応する `<session-id>.assets` ディレクトリも削除してください。`/fork` は新しいセッションに履歴のコピーを持たせるので、どちらも独立して削除できます。復元は、会話を切り替える前に計画と進捗を記録します。セッション再開時には、復元済みのファイルも含めすべてを再検査して中断された復元を完了します。競合があると追加の書き込みなしで回復を停止し、セッション開始時に通知します。復元完了まではファイルツールの書き込みとセッションのフォークはできません。まだ完了できる中断済みのコア復元は、会話だけの巻き戻しや拡張機能による復元を選ぶ前に完了する必要があります。後から記録を無効にした場合も同様です。競合や、ロックされたファイルなど今回の実行中のエラーで完了できない復元は、会話だけの巻き戻しを選ぶと放棄し、ファイルをそのままにします。ファイル復元が扱うのはバイト列であり、空ディレクトリやシェルの副作用ではありません。

checkpoints 拡張機能は `api.registerFileRestoration({ label, restore: async (index) => { /* restore bytes */ } })` で復元を排他的に担当できます。選択画面はそのラベルを表示し、ホストは会話を巻き戻す前にコールバックを呼び、コアの復元は実行しません。コールバックはファイルだけを復元し（`session.rewind` を再帰的に呼ばないでください）、競合時には例外を投げる必要があります。会話だけの巻き戻しでは呼び出しません。拡張機能のアンロードで担当を解放します。同時に復元を担当できる拡張機能は 1 つだけです。

## コンテキスト管理

セッションファイルは、すべてのメッセージとツール結果を常に完全な形で保持します。各モデルリクエストには、その履歴を用途に合わせて加工したものを送ります。大きな出力はプレビュー化し、繰り返しの読み取りは短縮し、コンテキストが埋まると古いツール結果を消去できます。プレビュー、`/context`、圧縮要約、サブエージェントのフォーク、親への相談は、すべて同じ加工結果を使います。一度短縮した結果を送ると、以降のリクエストでもまったく同じテキストを繰り返すため、プロバイダーのプロンプトキャッシュで接頭部分を維持できます。

**大きな出力。** 16,000 文字を超えるツール出力は、セッションファイルの隣の `<session id>.assets/outputs/` にアーティファクトとして全体を保存します（ファイルのないセッションではシステムの一時ディレクトリを使います）。代わりにモデルは約 8,000 文字のプレビューを受け取ります。最初の行にアーティファクト ID（`a_…`）、サイズ、続きを読み取る方法を示し、出力の先頭と末尾、行を省略した箇所の注記が続きます。サイズは文字数で数えますが、中国語・日本語・韓国語の文字は約 1 トークンに相当するため、1 文字を 4 文字分として扱います。このため、これらの出力はより早く保存され、プレビューも短くなり、`read` も早く停止します。`bash`、`powershell`、`grep`、`glob`（独自の結果制限をかける前に全結果を保存します）、MCP サーバーや他のツールの結果に適用します。`read` はアーティファクトを保存しません。長い範囲は上限内の行末で止まり、続きを読むための `offset` を示します。端末 UI では保存済み出力のプレビューを表示し、ヘッダーは短い控えめな行になります。

モデルは `output_read` でアーティファクトを読みます。`offset` と `limit` で行を選択し、`grep` で一致する行を返し（`ignore_case` で大文字と小文字を区別しません）、`column` で非常に長い行を分割して読みます。アーティファクトのファイルパスには `read` も使えます。アーティファクトが保持するのは、その時点でツールが返した内容です。元のファイルを読むと現在の内容が表示されます。

**繰り返しの読み取り。** `read` が、コンテキストに残る同じファイル・同じ行範囲の最新の読み取りと完全に同じテキストを返す場合、新しい結果だけを以前の結果への短い参照として送信します。以前の結果は書き換えません。範囲の内容が変わった場合、別の範囲の場合、以前の結果が圧縮・消去された場合は全文を送ります。モデルは `force: true` を渡して、同じ内容でもテキストを取得できます。

**古い結果の整理。** 次のリクエストがコンテキストウィンドウの 70% を超えると予測した場合、Amira は古いツール結果を一括で消去し、約 60% に減らします。消去した結果は以降、内容の概要と再取得方法を示す短い文に置き換えて送ります。`output_read` 用のアーティファクト ID、または再度 `read` するファイルを示します。直近 2 回のユーザーターン、長いターンでは最後の 2 モデルステップと、後続の呼び出しがまだ処理している結果は保持します。8,000 トークン未満しか解放できない整理（小さいウィンドウでは 70% と 60% の差に満たない場合）はスキップします。プロバイダーが履歴の書き換えを許可する箇所だけを整理します。リクエストに再送する署名付き・暗号化された推論より前の内容は変更しないため、そのようなモデルでは圧縮がこの役割を担います。長すぎるリクエストとして拒否された場合は、圧縮前に一度整理を試します。実験的な `afterTurns` オプションは、容量の逼迫に関係なく指定したユーザーターン数より古い結果も消去します。デフォルトでは無効です。

**アーティファクトの保持と削除。** アーティファクトはセッションと同じ期間保持し、自動削除はしません。1 セッションで最大 256 MB を保持します。保存枠を超えると出力はプレビューだけになり、保存できなかったことを明記します。`/prune` は、親と保存済みの各サブエージェントセッション別に、アクティブ（モデルが見るコンテキストに参照あり）、非アクティブ（圧縮済み・巻き戻し済みの履歴やサブエージェントの履歴にのみ参照あり）、未使用のアーティファクト数を示します。`/prune unused`、`/prune inactive`、`/prune all` はすべてのグループに同じルールを適用します。サブエージェントが実行中、キュー待ち、または待機中（永続的なエージェントが次のメッセージを待つ状態）の場合は、終了または停止まで削除を拒否し、読み取る可能性のあるものを残します。削除済みのアーティファクトを読むと、削除済みと通知します。

| 操作 | コマンド |
| --- | --- |
| アーティファクトの使用状況を表示します | `/prune` |
| 参照されていないアーティファクトを削除します | `/prune unused` |
| 古い履歴にだけ参照されているものも削除します | `/prune inactive` |
| このセッションの全アーティファクトを削除します | `/prune all` |

デフォルト値は設定の `context` で変更できます。

```json
{
  "context": {
    "outputs": { "saveAbove": 16000, "previewChars": 8000, "quotaMB": 256 },
    "dedupeReads": true,
    "aging": {
      "enabled": true,
      "start": 0.7,
      "target": 0.6,
      "minSavedTokens": 8000,
      "keepTurns": 2,
      "keepSteps": 2,
      "afterTurns": 0
    }
  }
}
```

`saveAbove` は 4000 以上、`previewChars` は 500 以上です（`saveAbove` を超えることはありません）。`start` と `target` は、0〜1 のコンテキストウィンドウに対する割合です。`dedupeReads` または `aging.enabled` を `false` にすると、それぞれを無効にできます。

## バックグラウンドタスクと監視

コマンドの出力を継続的に確認し、一致する行に反応する必要がある場合、モデルはポーリングせずに `monitor` を使えます。通常のバックグラウンドシェルジョブと異なり、監視は新しい出力でモデルを起動できます。

| `monitor` パラメーター | 意味 |
| --- | --- |
| `command` | 実行して監視するシェルコマンド |
| `filter` | 出力の各行に適用する正規表現。大文字と小文字を区別しません。無効な正規表現はリテラル文字列として扱い、その場合も大文字と小文字を区別しません |
| `timeout_ms` | ミリ秒単位の存続時間。デフォルトは 1,800,000（30 分）、最大は 7,200,000（2 時間） |
| `description` | 監視内容を示す任意の短い説明 |

ツールはジョブ ID を即座に返し、ジョブの種類は `kind: "monitor"` です。照合は行単位で、複数行にはまたがりません。一致した行は、モデルを起動する自動通知として届きます。約 1 秒間の出力をまとめ、送信は 2 秒に 1 回までです。各通知は約 4 KB を上限とし、`+N more lines` がその通知で省略した行数を示します。

行の組み立ては、起動中も含め、ジョブの保持出力バッファーから独立しています。65,536 文字を超える行はフィルター照合前に行全体を省略し、明示的に警告します。切り詰めた先頭や末尾を完全な行として照合することはありません。

通知イベントが 200 回に達すると、**notifications paused**（通知を一時停止）という制限通知が届きます。コマンドは動き続けますが、それ以降の一致した出力ではモデルを起動しません。さらに通知が必要なら停止し、フィルターを絞って新しい監視を開始してください。コマンドの終了時やタイムアウト時には最終通知が届き、タイムアウト時はコマンドも停止します。モデルはシェルジョブと同じように、ジョブ ID を指定して `job_stop` で監視を停止し、`job_list` と `job_output` で確認できます。

同じ所有者の監視が近い時刻に自然終了またはタイムアウトした場合、約 100 ミリ秒の範囲で最終通知をまとめ、一斉終了によるターンの連続起動を防ぎます。print モードやセッションの引き継ぎでも、配信まで通知の予約を保持します。ツールが終了を待っている場合や停止を要求した場合の最終通知は、アイドル中のモデルを起動しません。

監視は他のバックグラウンドジョブと同じ所有権とクリーンアップのルールに従います。メインセッションは自身のツリー内のジョブを確認でき、サブエージェントは自身のジョブだけを確認できます。サブエージェントの監視はその終了時に停止します。トップレベルの監視は `/clear`、`/resume`、`/fork` 後も存続し、置き換え先のセッションに引き継がれます。Amira の終了時には残るすべての監視を停止します。通知は所有する会話に届き、無関係なセッションには届きません。

### タスクの一覧表示、閲覧、停止

`/tasks` はサブエージェント、バックグラウンドシェルジョブ、監視をまとめて扱う入口です。一覧に表示された ID を使います。

| コマンド | 用途 |
| --- | --- |
| `/tasks` または `/tasks list` | すべての種類のタスクを一覧表示します |
| `/tasks view <id>` | タスクのライブ会話記録または出力を開きます |
| `/tasks stop <id>` | 指定したタスクを停止します |
| `/tasks stop all` | 待機中、アイドル中、一時停止中のサブエージェントを含め、終了していないすべてのタスクを停止します |

従来の `/jobs` と `/agents` も、それぞれジョブとサブエージェントの管理に引き続き使えます。タスクパネルはシェルジョブだけでなく、3 種類すべてを含みます。各サブエージェントの状態を表示し、実行中、待機中、アイドル中、一時停止中の件数を分けて示します。アイドル中や一時停止中のサブエージェントも、ID を指定して閲覧・停止できます。ライブビューを開けない場合、`/tasks view <id>` はツール呼び出しと結果のプレビューを含むサブエージェントの会話記録を出力します。ステータスの件数表示はエージェント、シェルジョブ、監視を区別し、待機中、アイドル中、一時停止中のエージェントを個別に示します。作業が実行中の場合のみ ASCII の実行インジケーターを表示し、0 件の項目は非表示にします。

## print モード

```sh
amira -p "Summarize the changes in this repository"
amira -p -c "Continue the review"
amira -p --json "Explain the failing test"
amira -p --json --json-coalesce "Explain the failing test"
amira -p --json-out events.json "Explain the failing test"
amira -p -- "-v means verbose?"
```

`-p` / `--print` は対話 UI なしで実行します。引数なしの `-r` でセッションを一覧表示する場合を除き、プロンプトが必要です。通常のモードでは、回答テキストを stdout に、ツールの実行状況、警告、エラーを stderr にストリーミングします。`--json` は print モードが必要で、各イベントを ASCII 文字だけの JSON 1 行として stdout に出力します。文字列の非 ASCII 文字は `\uXXXX` としてエスケープするため、Windows の親プロセスがコードページの不一致なしにストリームをデコードできます。`--json-out <path>` は `--json` を暗黙に有効にし、同じ JSONL イベントストリームを stdout ではなくファイルへ書き込みます。相対パスは Amira を呼び出した場所から解決します。各行は、最後の JSON 回答 1 つではなく、セッション、ターン、メッセージ、ツール、サブエージェントのイベントを含みます。

JSON の print 出力は空の `ui.render` イベントを省き、ツール呼び出し名はプロバイダーが変更しない限り最初の差分にだけ含めます。`--json-coalesce` は連続するテキスト、思考、同じツール呼び出しの引数の差分を大きな JSONL チャンクにまとめ、4,096 文字または 100 ms に達した時点で書き出します。指定しなければ、残る各イベントは別々の行になります。`--json-out` がエラーで終了しても、イベントファイルにストリームは残り、stderr に短い失敗の要約を出力します。

`amira -p "/status"` のように引用符で囲んだスラッシュコマンドは、モデルへプロンプトを送らず、そのコマンドを実行します。利用可能なスキルも同じ方法で実行できます。選択画面が必要なコマンドは対話的な回答を得られないため、対応している場合は引数を明示してください。

print モードは、実行中に開始したトップレベルのバックグラウンドシェルジョブを `backgroundJobs.printWaitMs`（デフォルト 30 秒）まで待ち、終了通知をモデルへ届けてフォローアップのターンを実行します。バックグラウンドのサブエージェントと、その結果から始まるフォローアップのターンも待ちます。ジョブの待機期限が切れると、通知を出力し、終了時にそのジョブを停止します。設定された予算は引き続き適用されます。結果の配信ターンが失敗した場合は、10、30、90 秒後に最大 3 回再試行できます。Ctrl+C は中断して待機を停止し、2 回目の Ctrl+C は強制終了します。終了コードは完了が 0、エラーが 1、ターンの中断が 130 です。

`-p` モードでは、実行中の監視が `expectNotice` の予約を保持します。一致した行の通知とフォローアップのターンを受け取るため、監視が停止、終了、タイムアウトするまで実行を維持します。通常のシェルジョブ用の `backgroundJobs.printWaitMs` によって監視が途中で終了することはありません。不要になった監視は停止してください。設定された予算と Ctrl+C の動作は引き続き適用されます。

## RPC による自動化

```sh
amira --rpc
amira --rpc-schema
```

RPC は stdin と stdout で JSON Lines を使います。`-p` や位置引数のプロンプトとは併用できません。`--rpc-schema` はプロトコルの完全なスキーマを出力し、モデルのターンを開始せずに終了します。起動時に再開するには `--resume <session-id>` または `-c` を渡します。RPC モードでは引数なしの `-r` は使えません。

1 行に 1 つのオブジェクトを送り、トップレベルに `id`、`cmd`、コマンドのパラメーターを置きます。モデルを設定済みの接続では、たとえば次のように送れます。

```json
{"id":1,"cmd":"prompt","text":"Explain the test layout"}
```

即時の応答にはリクエスト ID、`ok: true`、`turnId` が含まれます。これは開始の確認で、完了の確認ではありません。イベントは応答と混在します。結果を知るには対応する `turn.end` を待ってください。失敗したコマンドは `ok: false` と、`code` と `message` を持つエラーを返します。

| コマンド | 用途 |
| --- | --- |
| `prompt` | ターンを開始します。実行中は `busy` で失敗します |
| `steer` | 次のモデル呼び出しの前に指示を追加します。待機中ならターンを開始します |
| `abort` | ターンまたは圧縮を停止します |
| `state` | 状態、モデル、セッション、保留中の UI 要求を取得します |
| `session.read` | `what` パラメーターで `messages` または `lastTurn` を読みます |
| `session.resume` | `sessionId` で保存済みセッションへ切り替えます |
| `session.rename` | `title` で現在のセッションに名前を付けます。自動タイトルの場合と同様に `session.title` イベントが続きます |
| `session.fork` | 任意の `index` が示すユーザーメッセージの前で、新しいセッションへフォークします。理由が `fork` の `session.start` が続きます |
| `model.set` | provider/model 形式の `model` でモデルを切り替えます |
| `thinking.set` | `level` を `low`、`medium`、`high`、`xhigh`、`max`、`default` に設定します。実行中は `busy` で失敗します |
| `command.list`, `command.complete`, `command.run` | スラッシュコマンドを検索・実行します |
| `skill.list`, `skill.run` | スキルを検索・実行します |
| `ui.respond` | `requestId` と `value` で UI 要求に回答します |
| `ui.action`, `ui.configure`, `ui.focus` | フォーム操作、フォーム表示、クライアントのフォーカスをサポートします |

パラメーターの構造と UI 回答の型は生成されたスキーマを参照してください。たとえば確認には boolean の `value` を使います。明示的な `null` はキャンセルになり、`value` の省略は無効です。要求を開いたまま、後続の入力行で回答できます。遅いクライアントが `events.lost` を受け取った場合は、`state` と `session.read` で再同期してください。実行中も stdout を読み続けてください。

`thinking.set` には明示的な `level` が必要です。欠落や無効な値は `invalid_params` を返します。`default` は推論の強度を送信せず、フラグや設定に戻るのではなく、それらを上書きします。応答と `state` には `supportsThinking`、非対応のモデルでも有効な `thinkingLevel`、現在のモデルへ強度を送る場合に限って `thinking` が含まれます。サーバーのデフォルト値を使う場合は、両方の強度フィールドを省略します。`default` は思考を無効にしません。Claude 5.x モデルはデフォルトで思考し、Amira に `off` の選択肢はありません。Anthropic は Opus 5.5、Fable、Mythos の思考無効化を拒否します。Sonnet 5.5 で最初の思考を省くには `between_tools` が必要です（ツール呼び出しの間には引き続き思考できます）。

stdin を閉じると、バックグラウンドの結果とフォローアップのターンを含む実行中の作業を待ち、誰も回答できないダイアログはキャンセルします。ダイアログを使うコマンドでは、完了まで stdin を開いたままにしてください。

## 状態と費用

`/status` はモデルとプロバイダー、セッション、コンテキスト使用量、出力トークン、キャッシュヒット率、費用、権限、ワークスペースを報告します。速度は最大 3 つの短い行で示します。最後のプロバイダーリクエストの総出力速度と TTFT、任意の思考・回答の内訳、最後に完了したターンの実効 TPS です。

すべての時間はイベントのタイムスタンプを使い、秒単位です。`O` は報告された `usage.output`、`R` は報告された `usage.reasoning`（すでに `O` に含まれます）、`T` は最初のコンテンツブロック開始または差分から最後のプロバイダーイベントまでの時間、`H` は思考ブロックの開始から終了までの時間の合計とします。

- **出力速度：** `O / T`。思考とツール呼び出しの出力を含む主要な指標です。
- **TTFT：** 最初のコンテンツイベントの時刻からリクエスト送信時刻を引いた値です。空の思考ブロックや差分も数えます。最初に見える回答テキストまでの時間ではありません。再試行ではリクエストの計時をやり直します。
- **内訳：** 思考は `R / H`、回答は `(O − R) / (T − H)` です。推論トークン数の報告、完全なブロックの時間計測、思考表示の省略または生のストリーミング推論が必要です。要約を要求した場合は内訳を表示しません。サーバーのバッファリングにより時間計測が意味を持たなくなるためです。要約モードはリクエストのメタデータから判定し、要約の長さからは判定しません。
- **ターンの実効 TPS：** ターン内のプロバイダーリクエストで報告された出力の合計を、プロンプト送信からターン終了までの実時間で割った値です。ツール、再試行待ち、圧縮を含みます。サブエージェントとバックグラウンドのタイトルリクエストは含みません。

出力数が報告されない場合は、印（`~`）を付けたテキストに基づく推定値を使います。総出力数が報告されていれば、推論トークン数がなくても正確な値です。推論トークン数がない場合は、印付きの内訳の推定値を維持します。表示モードが不明な場合、非表示の推論には従来の `reply ~N tok/s (hidden reasoning)` という推定表示を維持します。回答トークン数の報告があれば引き続き使いますが、段階別の時間は概算です。要約を要求した場合は内訳を表示しません。また、生の推論または省略表示と分かっていても、思考ブロックの時間計測が不完全なら、正確な内訳を作り出すことはありません。

TUI の実行状況行は、ターンの経過時間と出力トークン数を表示し、tok/s は表示しません。ストリーミング中の推定値は、各回答の終了時に報告された出力数で置き換えます。フッターに速度表示はありません。省略された思考は、実行中の秘匿された思考と同様に TUI の推論行を持ちません。署名付きブロックは変更せずに保存・再送します。再開したセッションは以前の使用量を含みますが、速度は今回の実行のイベントからだけ計測します。ステータスバーは現在の実行開始以降のエージェントツリーの使用量を報告します。`/status` は保存済みセッションとサブエージェントの費用も含められます。

`/cost` はこのセッションの回答をモデル別に報告し、圧縮とセッションタイトルのリクエストを別に示します。子エージェントの費用は合算しません。それらには `/status` と `/agents` を使ってください。費用は既知のモデル料金と報告された使用量に基づきます。不明な料金は明示し、料金不明の行を含む合計は部分的な推定値です。実際の請求額はプロバイダーの請求情報を確認してください。
