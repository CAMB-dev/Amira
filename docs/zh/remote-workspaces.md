# 远程工作区

[English](../remote-workspaces.md) · [日本語](../ja/remote-workspaces.md) · [文档首页](../../README.zh-CN.md)

远程工作区在 Linux 主机上运行 agent、工具和会话，全屏终端界面则在你的电脑上运行。通过 SSH 连接，不会挂载文件系统或同步项目。默认情况下，模型请求经由本地 provider 连接发送，provider 密钥留在本机。

## 环境要求

- 本机安装系统 OpenSSH（`ssh`），且身份验证和主机密钥校验正常。身份文件、端口和 ProxyJump 通过 SSH 配置别名设置；远程命令接受别名或 `[user@]hostname`，不接受 SSH 选项或 URL。
- 远程主机为 Linux，使用 glibc 2.28 或更新版本，架构为支持 SSE4.2 的 x64 或 ARM64。不支持 musl/Alpine 或其他远程操作系统。
- 远程工作区目录已存在，远程主目录可写，并提供标准 Linux shell 工具，包括 `getconf`、`sha256sum` 和兼容 GNU 的 `stat`、`mv`。安装不需要 sudo，也不需要在远程安装 Bun。
- 客户端带有可信的服务端发布公钥，并有匹配的签名服务端产物。发布版客户端会**在本机**下载并缓存缺少的产物；远程主机不下载服务端二进制文件。
- 附加需要交互式终端；`TERM=dumb`、打印模式和旧版 RPC 都不能作为远程前端。

Amira 使用 SSH 标准输入/输出，不分配 PTY，也不转发 SSH agent。请先通过正常的 SSH 配置完成认证并核验主机密钥；Amira 不会绕过这些检查。

## 添加并附加

```sh
amira remote add devbox --name project --cwd /home/dev/project
amira remote attach project
```

`add` 探测主机、安装服务端并保存本地目标，不打开界面。批准安装及今后的自动二进制更新前，请核对显示的 SSH 用户、安装位置、服务端版本/构建标识和模型模式。`attach` 也可以直接对主机执行首次设置：

```sh
amira remote attach devbox --cwd /home/dev/project
```

`--cwd` 必须是绝对 Linux 路径，不能是 `~` 或本地路径。不指定时，已有目标沿用保存的工作区，新主机使用远程主目录。附加时在远程解析工作区的规范路径。提供的工作区会成为该目标保存的默认值。目标名称以字母或数字开头，只能包含字母、数字、点、下划线或连字符，最长 128 个字符。

非交互式安装授权使用 `--accept-install`（别名为 `--yes`）。它授权安装和自动更新，不代表批准 provider 绑定。`attach` 仍然需要终端。

```sh
amira remote add devbox --name project --cwd /home/dev/project --accept-install
```

使用离线产物时，在每次需要它的调用中提供本地 bundle 目录：

```sh
amira remote attach project --bundle /path/to/signed-server-bundle
```

目录包含 `server-manifest.json`、保存 base64 Ed25519 签名的 `server-manifest.json.sig`，以及对应的原始可执行文件：`amira-server-bun-linux-x64-baseline` 或 `amira-server-bun-linux-arm64`。清单必须匹配客户端版本和明确的构建标识，bundle 不能提供自己的信任公钥。开发检出需要签名的本地 bundle 和明确的开发用 `AMIRA_SERVER_BUILD_ID`；仅有包版本号并不足够。

运行 `amira remote --help` 查看远程选项。`remote add` 和 `remote attach` 不接受 `--model`、`--resume`、`-p`、`--extension` 等普通启动标志。只有 `--name` 仅用于 `add`，其余已说明的远程选项均适用于两者。目前没有 `remote list`、`remote remove` 或 `remote stop` 客户端命令。

## 模型与凭据

### 默认：本地 provider 连接

远程设置决定使用哪些模型，包括子 agent、标题和压缩模型。按 [Providers](providers.md) 和[设置](settings.md)在远程配置这些 provider/模型引用，在本机配置对应的 provider 凭据。绑定要求本机具有相同 provider ID 和协议（dialect）。Amira 不会用本地模型列表替换远程列表，也不提供通用的 provider 别名映射。

界面打开前，Amira 会询问是否允许某个远程 provider 使用指定的本地 provider 账户和端点。请核对远程预期端点、本地端点和计费账户。这与远程工具审批是两项不同的授权：它允许使用该本地账户发送模型请求，而非读取密钥。远程端点不会决定本地密钥的发送目的地。

授权回执保存在本地 Amira 主目录下的 `remote/bindings`。它们保存哈希，不保存 provider 密钥、请求头或带凭据的 URL，并限定于 SSH 目标/工作区及绑定身份。凭据、端点或远程 provider 身份变化会使对应授权失效。绑定缺失或被拒绝时，该模型保持不可用；请在本机完成配置和授权，然后重新附加。不会自动回退到远程凭据。

推理所需的提示词、工具结果和图片会经过本地内存发送给 provider。密钥留在本机，并不表示工作区内容不会经过本机或发送给 provider。

### 显式使用远程凭据

```sh
amira remote add devbox --name remote-models --cwd /home/dev/project --remote-key
amira remote attach remote-models
```

`--remote-key` 使用远程主机上配置的 provider 凭据，并在远程发送 provider 请求，不会复制本地 provider 密钥。选定模式随目标授权一起保存：以后即使不带此标志，附加该目标仍使用 remote-key 模式。省略此标志不会恢复本地代理模式，目前没有 `--local-proxy` 开关。

运行中的守护进程保留启动时的模型模式；修改目标授权不会更改该进程。确认其工作后，先显式停止它，再以另一模式启动工作区。不兼容的附加会被拒绝，而不会悄悄切换凭据。

## 两台电脑各负责什么？

| 远程主机 | 本机 |
| --- | --- |
| Agent、内置工具、shell 命令、任务、子 agent 和工作区文件 | 全屏渲染、剪贴板、外部编辑器和终端交互 |
| Agent 设置、provider/模型定义、权限、信任、指令、skill 和 MCP 配置 | 用户级主题、按键绑定和 `tui` 设置；不加载本地项目设置/主题 |
| 保存的对话及 `/resume`、`/clear`、分支、回退等会话操作 | 本地 Amira 主目录的 `remote` 下保存的 SSH 目标记录、产物缓存和 provider 绑定回执 |
| 仅在显式 remote-key 模式下使用 provider 凭据 | 默认本地代理模式下的 provider 凭据与 HTTP 请求；输入历史仅留在内存中 |

普通[设置优先级](settings.md)在远程主机上生效。本地配置不会整体同步或转发。`AMIRA_HOME` 选择本地 Amira 主目录；SSH 安装程序使用远程用户的 `$HOME/.amira/remote`，启动器位于 `$HOME/.amira/remote/bin/amira-server`。

远程模式只运行内置的可执行扩展。已安装或显式配置的可执行扩展会被跳过并显示通知；其自定义工具、命令和视图不会因此获得远程支持。远程仍可发现可信包中的 skill 数据。内置配置包含工具、skill、MCP、web、状态和子 agent，但不提供 `/provider` 或 `/ext` 管理。请在附加界面之外管理远程 provider 设置和包。本地安装的扩展也不会在远程前端执行。参见[扩展](extensions.md)。

## 文件、图片和链接

- `@` 补全列出的是**远程**文件；聚焦子 agent/worktree 时也使用相应的远程范围，不会浏览本地检出目录。
- 在 `@` 中选择远程图片会从远程主机读取；粘贴/拖入的本地图片路径和剪贴板图片会在本机读取并上传字节。本地相对路径以启动客户端时的目录为基准，而非远程工作区。不会把本地路径交给服务端当作可打开的文件。
- 支持普通图片格式，**每条消息总计 5 MB**，且选中的模型必须支持图片。参见[图片](usage.md#图片)。
- 远程文件路径以文本显示，不生成可点击的本地文件/编辑器链接。远程模式下，仅 HTTP(S) 目标可成为终端超链接。

目前没有文件同步、端口转发功能、远程编辑器桥接、容器启动器或 WSL 启动器。打开本地编辑器编辑的是本地草稿，不是远程项目文件。

## 分离、停止与重连

每个远程用户 + 规范工作区由一个守护进程拥有，只有一个活动主对话和一个控制端。不支持只读查看模式或多个并发控制端。已有控制端持有工作区时，其他客户端会被拒绝。连接关闭后，控制权最多保留 30 秒，新附加可能需要等待。超过这一分离保留期，旧重连凭据就会失效，即使其绝对最长有效期为 24 小时。任一期限届满后，请退出并重新运行 `amira remote attach`；`/reconnect` 无法修复已过期的控制权租约。

- **分离：**`/quit` 退出本地界面并断开连接，不会停止守护进程、运行中的工具、后台任务、子 agent 或远程待处理审批/问题。关闭终端也会移除本地模型代理。
- **停止一轮：**Esc 停止当前轮次（若有运行中的斜杠命令，则先取消该命令），不会停止所有后台任务或子 agent。请用 `/tasks` 和 `/agents` 的控件分别停止它们。
- **停止工作区：**以相同 SSH 用户**在远程主机上**运行下列命令。它会明确停止守护进程及其活动工作，并非分离命令。

```sh
"$HOME/.amira/remote/bin/amira-server" stop --cwd /home/dev/project
```

临时 SSH 中断会触发自动重连。每次新连接都会重新探测设置并校验签名产物。认证/主机密钥失败、远程身份/平台变化、产物被拒绝、安装错误或守护进程不兼容会停止自动重试并显示恢复通知。修复原因后，使用本地 `/reconnect`。如果需要改变授权，请分离并重新运行 `remote add` 以核对授权；`/reconnect` 不会授予同意或绕过验证。

本地代理模式下，没有客户端时远程工具/任务仍可继续，但下一次模型请求要等待获准接入的本地代理。默认等待 10 分钟，超时以网络故障结束受影响轮次，不视为用户中止。已经尝试过的 provider 调用只能在同一个本地进程中、有限保留期内恢复同一次调用；丢失后不会自动重新发起一次付费请求。退出/崩溃会丢失该代理的内存，新附加无法恢复旧 provider 流。remote-key 模式不依赖本地代理。

重连活动守护进程不同于 `/resume`（选择保存的对话历史），也不同于守护进程重启。重放仅保存在内存中，最多 **32 MiB 或 50,000 个事件**，先达到任一上限即受限。游标过期或守护进程 epoch 变化会触发快照重新同步，其中包含仍然存在的当前运行/待处理状态，但不会恢复过去的每个瞬时事件。保存的会话并非无限事件日志。

守护进程崩溃、主机重启或空闲退出后，新守护进程打开该工作区最近保存的对话，不能复活运行中的工具、操作系统进程、任务、审批对话框或 provider 流。只能使用已经保存的历史；重连不等于崩溃恢复。

### 超时

在**远程主机**上设置，而非本地前端设置中：

```json
{
  "remote": {
    "idleTimeoutMs": 1800000,
    "proxyReconnectTimeoutMs": 600000
  }
}
```

`idleTimeoutMs` 默认为 30 分钟，只在分离且真正空闲时生效：没有运行工作、待处理模型调用、审批/问题或任务。因此待处理审批可能无限期保留守护进程。`proxyReconnectTimeoutMs` 默认为 10 分钟，控制等待本地模型连接的时间，不控制控制端保留时间或已接受调用的保留期。两者都接受 `0` 到 `2147483647` 的整数毫秒；`0` 分别表示禁用空闲退出或无限等待代理接入。空闲超时在守护进程启动时读取；重载设置可更新后续代理等待，但不会重启已经尝试的调用或改变代理的保留上限。

## 更新

设置授权包括该 SSH 身份/安装位置和模型模式下，今后自动安装匹配的签名二进制更新。每次连接会校验本地产物的签名、大小、哈希及构建身份；上传后在远程再次校验，然后原子替换启动器。更新失败会保留之前可用的启动器和构建。

安装新可执行文件**不会**停止活动守护进程。兼容的运行构建可继续附加，通知会显示已安装与运行中的版本/构建标识。替换要等到工作区没有控制端/中继连接、活动工作或待处理请求。完成工作并分离，让旧进程退出，再重新附加。不兼容的运行构建会拒绝附加；请等待空闲退出，或在确认后果后显式停止工作区。Amira 绝不会为绕过不兼容而启动第二个拥有者。

## 需主动选择执行的 Linux/SSH 维护者清单

这是手动平台验收门槛，**不属于**自动离线 CI，也不表示 Linux 或真实 SSH 已获验证。Windows 原生夹具和伪 SSH 不能证明 Linux x64/ARM64 支持。仅在维护者明确同意后，使用可丢弃主机/工作区和隔离的客户端/服务端账户与主目录执行。使用行为确定、由维护者控制的模拟模型端点和虚拟凭据，阻止真实 provider 访问，无需产生真实计费。模拟端点是测试夹具，不是远程 CLI 标志。

- [ ] 记录客户端/服务端版本、构建标识、签名产物哈希、架构、发行版/glibc、CPU 和 OpenSSH 版本。在未安装 Bun 或 Node 的环境中分别执行实际 Linux x64 和 ARM64 产物，并验证进程/stdout worker 及 shell 工具；仅交叉编译不算通过。检查不读取设置的 `--version-json` 与 `--self-check`。
- [ ] 验证真实 OpenSSH 别名、用户/端口/密钥配置和 ProxyJump。确认未知/变化的主机密钥及认证失败不会绕过验证或无限重试，且不请求 PTY 或 agent 转发。测试带空格/引号的路径、stderr 横幅及非登录 PATH；stdout 必须保持有效 JSONL。
- [ ] 检查 glibc/CPU 拒绝、必需工具、主目录所有权/权限、私有本地文件系统 socket/元数据/日志、过长的工作区/socket 路径、过期 PID/锁恢复及 XDG runtime 回退。确认其他用户不能附加、替换元数据或读取私有日志；不要放宽权限以强行通过。
- [ ] 阻止远程下载，用签名本地 bundle 安装。中断真实上传，测试主目录磁盘已满或挂载为 noexec、校验工具缺失、bundle/哈希/签名损坏及并发设置。确认失败不破坏可用启动器，且只发布匹配并通过验证的字节。
- [ ] 配置匹配的远程/本地模拟模型 ID/协议。在本地批准绑定；测试拒绝、缺失绑定、端点/凭据变化及回执失效。仅采集虚拟哨兵值，确认它们不会以凭据形式出现在远程协议输入、会话或日志中。单独测试 remote-key 模式及不回退本地密钥。
- [ ] 执行内置文件编辑及长时间远程 shell 任务；验证审批、问题、实时表单、子 agent 聚焦/停止、任务输出/停止、会话切换、状态/用量及图片引导。确认跳过的可执行扩展有通知且不会执行，并检查远程 `@` 文件/图片及不可点击的文件链接。
- [ ] 在工作及待处理对话框期间仅断开 SSH 中继，并在控制权保留期内重连。确认不重复提示词、审批、表单操作/提交或付费调用，不意外中止任务/轮次。测试离线表单编辑/Save/Cancel 和过期回复。
- [ ] 验证实际延迟、大型文件列表/图片上传、频繁输出的任务、海量输出与背压；检查内存有界、输入响应及时、取消操作不被阻塞。测试截断帧/EOF，以及完整但非法的帧。超出重放保留上限，确认快照恢复不重放前端动作。测试第二控制端，以及超出控制权保留期/令牌有效期后的重连，确认恢复提示明确指向重新附加。
- [ ] 代理连接中断时保持客户端运行，再分别测试代理保留期届满和客户端进程内存丢失。确认代理未接入仅以网络故障结束一次轮次，无关任务继续存活，不盲目重发已接受的调用。
- [ ] 比较 `/quit`、轮次/任务/子 agent 停止与显式工作区停止。检查分离后空闲退出、待处理审批保留守护进程、超时覆盖与零值。
- [ ] 在活动工作期间安装新签名构建。检查安装/运行通知、完成工作并分离后的兼容退出，以及不兼容拒绝且不启动第二守护进程或强制停止。包含相同构建标识但不同版本的情况。
- [ ] 按主机实际策略测试 SSH 注销/SIGHUP、会话管理器清理、杀死守护进程及主机重启。确认仅恢复保存的历史，不恢复运行进程/对话框/流；检查孤儿进程处理，不承诺进程复活。
- [ ] 按平台/用例记录通过、失败或未运行，附脱敏证据及剩余缺口。将真实 Linux/SSH 结果与离线协议/模拟测试、Windows 原生打包结果分开记录。

某些登录管理器会在注销时终止该用户的所有进程。SSH 分离无法绕过主机策略。如有需要，使用经管理员批准的用户级进程监管服务或 linger 策略，并单独验证；Amira 安装本身不需要 sudo。
